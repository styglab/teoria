# kordoc 차이 수정과 재검증 — Python 0.2.0

2026-10-20. `archive/kory_parser/`의 독립 설치 패키지만 수정했다.
활성 Platform·Pipelines·Prefect에는 연결하지 않았다. 파싱에 Node.js는 필요하지
않으며 원본 kordoc 4.22.15 비교 실행에서만 사용한다.

## 수정한 동작

- **HWP**: 본문과 메모의 레코드 깊이를 구분해 메모 혼입을 제거했다. `tcps` 조합
  번호, 머리말/꼬리말 배치, inline 표 뒤 문단 연결, 셀의 중첩 표 평탄화를 보완했다.
  원시 PUA는 구조화 결과에 보존하고 Markdown 표시 단계에서 치환한다. 내장 이미지
  참조에서 안정적인 이름을 복원해 빈 이미지 자리와 실제 그림을 구분한다.
- **XLSX**: 기본 `sheet_layout="compact"`는 비어 있는 행·열을 제외한다. 셀의
  `source`에는 실제 Excel 주소를 유지한다. `sheet_layout="source"`를 선택하면
  원본 행·열 좌표를 그대로 격자로 표현한다.
- **PDF 표**: PDF 연산자의 사각형 clipping 정보를 추출하고 인접·포함 관계를
  판별한다. 짧은 점선과 음영 셀, 흰 배경과 실제 선을 구분한다. 일부 clipping이
  없는 셀도 격자 안의 텍스트로 복원한다. 중첩 표 전후의 문구가 중복되거나
  사라지지 않도록 셀 내부 읽기 순서를 재구성한다.
- **PDF 텍스트**: 중복 glyph와 NUL을 제거하고, 글꼴이 바뀌는 위치의 문장부호
  순서를 보존한다. 원형과 숫자가 실제로 겹칠 때만 원문자 숫자로 조합한다.
  목차의 점선 leader·soft hyphen과 빈 후행 열도 처리한다.
- **결과 계약**: 표의 `geometry_source`와 원문 영역을 보존한다. 후행 빈 열
  기본값은 HWP/HWPX/HWP3에서 유지, 나머지는 제거다. 명시적 옵션이 우선한다.

원본 MIT 알고리즘을 참고·이식한 부분과 rhwp 유래 문자표는 `NOTICE`와 license에
기록했다. PDF 전체 알고리즘의 완전 이식을 의미하지 않는다.

## 실제 문서 재비교

| 형식 | 표본 | 0.1.0 일치 | 0.2.0 일치 |
|---|---:|---:|---:|
| HWP | 21 | 12 | 21 |
| HWPX | 10 | 10 | 10 |
| PDF | 32 | 5 | 12 |
| DOCX | 1 | 1 | 1 |
| XLSX | 2 | 0 | 2 |
| PNG | 2 | 0 | 0 |
| **전체** | **68** | **28** | **46** |

주요 10개는 **6/10 → 7/10**이다. 기존에 일치했던 28개는 모두 일치를 유지했다.

"일치"는 양쪽 성공과 **정규화 본문 + 모든 표의 행·열·anchor·span·셀 내용** 일치다.
글꼴·이미지·조판·의미 정확도 전체 일치가 아니다. 같은 68개 개발 표본을 재사용했으며
독립 holdout 검증은 아니다. 주요 10개는 이 68개에 포함되어 합산하지 않는다.
OCR·수식 OCR·이미지 바이트 추출은 양쪽 모두 껐다. 동일 입력 SHA-256, 원본
버전과 Python 소스 hash를 확인했고 비교 중 소스 변경이 없음을 검사했다.

[0.1.0 최초 결과](comparison_2026_10_20.md)를 보존하고 새 숫자·입출력 hash는
[68개 결과](../verification/results/corpus_68_v0_2_0.json),
[주요 10개 결과](../verification/results/primary_10_v0_2_0.json)에 별도 저장했다.

## 남은 차이와 원본 자체의 문제

- 일부 PDF의 페이지 간 표 연결, 행 분할과 도식 읽기 순서는 다르다. 예를 들어
  `corpus_013/033/037/058`은 문자는 같아도 표 구조까지 일치하지 않는다.
- `corpus_004`는 원본에서 출력하는 일부 PUA·기호의 해석 차이가 남는다.
- `corpus_005`에서 원본은 서로 다른 요구사항 ID가 있는 양식을 연결하고 반복
  항목명을 생략하는 경우가 있다. Python의 별도 표를 무조건 합쳐 점수를 올리지 않았다.
- `corpus_041/044`의 일반 법령 문장이 원본에서 표로 분리된다. `corpus_041`은
  원본 PDF의 해당 페이지를 렌더해 일반 문장임을 확인했다. Python은 문단을 유지한다.
  이 차이를 Python 오류로 자동 분류하지 않는다. 전체 코퍼스를 시각 검수한 것은 아니다.
- 텍스트 없는 PDF 2개는 Python에서 `NEEDS_OCR`다. 원본은 success를 반환하지만
  빈 본문 수치 일치를 내용 복원 성공으로 세지 않는다. PNG 2개도 OCR을 꺼서 실패한다.
  암호화 PDF 1개는 양쪽 실패다. 실행 성공 수는 Python 63/68, 원본 65/68이다.
- 주요 `doc_04`는 중첩 내부 표가 7×3에서 11×3으로 복원되어 본문·셀까지 일치한다.
  `doc_10`은 추출된 문자는 같지만 표가 원본 2개/Python 3개로 다르며 이미지 속
  규격은 OCR 없이 복원되지 않는다. `doc_01`도 원본 14개/Python 25개로 다르다.
- 실제 HWP3/HWPML/XLS/PPTX 표본, 수식·서식·조판 전체 호환은 이번 검증 범위 밖이다.

## 검사와 패키지

- 단위·회귀 테스트 **49개 통과**, Ruff 정적 검사·형식 검사 통과.
- 새 테스트는 메모 혼입·머리말/꼬리말·조합 숫자, 점선/음영/중첩 표, clipping
  누락 셀, 흰 배경 오탐, 글꼴 경계 문장부호, 실제 겹침 숫자 복원을 검증한다.
- 0.2.0 wheel과 sdist를 빌드하고 격리 환경에 wheel을 설치해 HWPX·PDF 파싱을
  확인했다. 외부 프로세스 호출을 금지한 상태로 실행했다.
- 배포물의 새 PDF 모듈·문자표·MIT 고지를 확인했다. 실제 문서와 native JSON은
  `.artifacts/`에만 남기며 배포하지 않는다.
- OCR 코드는 변경하지 않았고 이번에는 OCR 모델 인식을 재실행하지 않았다.
  이전 한국어 1줄 smoke 결과는 0.1.0 검증 기록이다.
- [소스·의존성 근거](../verification/provenance_v0_2_0.json)와
  [빌드 hash](../verification/build_artifacts_v0_2_0.json)를 함께 남겼다.

이 결과는 원본과의 일치 개선을 보여준다. 남은 PDF 차이까지 모두 해결되거나
운영 Prefect 배포가 검증된 상태는 아니다. 설치·옵션은 [사용 안내](usage.md)에 있다.
