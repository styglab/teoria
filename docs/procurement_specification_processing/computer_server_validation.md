# 컴퓨터서버 첫 검증과 공통 선별기 구현 기록

> 과거 파서 실험 기록이다. 첨부 후보 선정 코드와 전용 테스트는 삭제했으며 현재 실행은 [의미 분석 배치](verification/retired_semantic_batch.md)를 따른다.

검증일은 **2026-10-20**이다. 첫 검증 품목은 원천 세부품명번호 **4321150102
(컴퓨터서버)**이며, 처리 구조는 물품에 독립적으로 설계한다. 이번에 구현한 것은
메타데이터의 **확인 우선순위**다. 실제 규격 포함 여부를 확정하는 분류기·전체 파싱
모듈·Requirement IE·운영 파이프라인은 완성하지 않았다.

현재 규칙은 [후보 식별 설계](document_identification.md)를 따른다. 이전 v1~v7 실험은
삭제 상태로 유지하며 그 후보 발견률을 이번 성능으로 사용하지 않는다.
이 문서는 초기 최소 검증 기록이다. 이후 새 20개 공고에서 수행한 실제 선별
평가와 v2 수정은 [선별 적정성 평가](selection_evaluation_2026_10_20.md)에 별도로 기록했다.

## 1 실행 범위

| 작업 | 실제 실행 |
|---|---|
| 기존 5개 문서 확인 | 원본 SHA-256 대조, 메타데이터·기존 미리보기와 파싱 결과 확인 |
| 최소 파싱 | kordoc 4.22.15, Node 20.20.2, OCR·이미지 추출 끔 |
| 공통 선별기 | 파일명·명시적 원천 참조로 확인 우선순위 결정. 품목별 분기 없음 |
| 개발 자료 점검 | 기존 서버 공고 20건·첨부 메타데이터 84개 |
| 추가 진단 표본 | 기존 20건을 제외한 2026년 서버 코드 공고에서 고정 무작위 2건 |
| 추가 다운로드 | 2건의 전체 첨부 7개, 총 1,177,721 bytes(약 1.12MiB) |
| 총 파싱 | 기존 5개 + 추가 7개 = 12개, 전부 파서 success 반환 |
| 운영 연결 | 없음. Flow·API·Registry·배포·DB migration 변경 없음 |

추가 문서 다운로드 예산은 파일당 5MiB, 총 20MiB였고 HTTPS 나라장터 주소와
동일 허용 호스트의 제한된 redirect만 사용했다. 새 문서 형식은 magic signature로
확인하고 SHA-256을 보존했다. 파서 의존성 설치는 이 문서 파일 전송량에 포함하지 않는다.

## 2 기존 5개 문서의 최소 파싱 결과

| 공고번호 / 슬롯 | 형식 | Markdown 문자 수 | 반환 표 수 | 반환 셀 수 | 병합 셀 수 |
|---|---|---:|---:|---:|---:|
| R26BK01779907 / 3 | HWP | 1,708 | 1 | 56 | 11 |
| R26BK01779838 / 3 | HWPX | 3,438 | 2 | 25 | 0 |
| R26BK01768647 / 5 | PDF | 3,981 | 3 | 33 | 6 |
| R26BK01779348 / 4 | HWP | 1,448 | 2 | 24 | 8 |
| R26BK01779237 / 4 | HWP | 1,105 | 1 | 12 | 4 |

문자 수는 파서 Markdown 길이이며 원문 문자 수와 같다는 뜻이 아니다. 표·셀 수는
파서 IR의 배열 집계다. 병합으로 덮인 빈 placeholder 셀이 포함될 수 있으므로
값이 있는 셀 수·논리 셀 수와 구분해야 한다.

HWPX는 원본 ZIP의 section XML에서 표 2개·셀 25개를 별도로 세어 파서 결과와
집계가 일치함을 확인했다. 이 비교만으로 모든 텍스트·읽기 순서·시각적 구조의
완전성을 검증했다고 주장하지 않는다.

HWP 문서의 기존 점검은 약 1,023자 내장 미리보기였다. 이번에는 kordoc의 본문
파싱을 실행했다. R26BK01779348은 서로 다른 구성의 워크스테이션 표 2개가 반환돼
한 파일의 여러 품목·구성을 분리해야 하는 사례가 됐다.

## 3 실제로 확인한 구조와 의미상의 주의점

### 요구규격 열과 업체 기입란

R26BK01779237과 R26BK01779348에는 `입찰 공고 규격`과 `업체 제시 규격` 열이
함께 있다. 두 열을 모두 발주자의 요구규격으로 추출하면 안 된다. 예를 들어
R26BK01779237의 원시 JSON에서 `/blocks/1/table/cells/1/0/text`와
`/blocks/1/table/cells/1/2/text`에 각 열 제목이 있다. CPU 요구 내용은
`/blocks/1/table/cells/2/0/text`에서 확인했다.

이 경로는 특정 parser output 안의 JSON Pointer다. 원본 문서의 영구 ID나
정규화된 Document JSON의 최종 계약으로 간주하지 않는다.

### 서버 코드와 실제 발주 물품

추가 표본 R26BK01665499는 서버 코드로 조회됐지만 상세규격에는 AI 학습용
그래픽카드의 GPU 연산·메모리 사양이 적혀 있다. 공고의 서버 코드와 실제 납품
물품의 정체성을 동일하게 취급하지 않는다. 코드 범위의 조회와 본문 품목 식별을
분리해야 하며, 이를 서버 요구규격 회수 성공으로 바로 집계하지 않는다.

### 예시 규격과 발주 요구규격

R26BK01540698의 `규격입찰 설명서`에는 규격입찰서 제출 지침·평가 관련 서식과
분광광도계의 예시 규격이 있다. `규격` 또는 수치가 나온다는 이유로 실제 서버
요구조건으로 등록하면 안 된다. 실제 구매규격서는 별도 PDF였다.

### 파싱과 조건 검증의 구분

추가 서버 구매규격서에는 메모리 `512GB`와 구성 표기 `32GB × 12`가 함께
관측됐다. 이를 자동으로 384GB 또는 다른 구성으로 고치지 않고 원문 표현과
불일치 가능성을 보존해야 한다. 현재 이 조건의 의미 판단·정정·적합 판정은 수행하지 않았다.

## 4 추가 표본 2건의 점검

2026년 물품 공고의 최신 차수에서 취소 공고를 제외하고, 기존 20개 공고를 제외한
서버 코드 집단을 사용했다. 공고번호·차수·고정 seed `server_content_probe_v1`의
MD5 정렬 상위 2건을 규칙 작성 후 선택했다. 계약 유형·첨부 존재 여부로 추가
선별하거나 결과를 보고 다른 공고로 교체하지 않았다. 읽기 전용 SQL을 보존했다.

| 공고번호 | 첨부 | 메타데이터 우선순위 | 파싱 내용에서 관측한 역할 |
|---|---|---|---|
| R26BK01540698 | 공고문 HWP·PDF | 수동 확인 2개 | 공고 조건과 별도 규격 참조 |
| R26BK01540698 | 규격입찰 설명서 HWP | 수동 확인 1개 | 제출 지침·서식·다른 장비 예시 |
| R26BK01540698 | 구매규격서 PDF | 우선 확인 1개 | 서버의 정량적 기술 요구규격 |
| R26BK01665499 | 공고문 HWP·PDF | 수동 확인 2개 | 공고 조건과 별도 규격 참조 |
| R26BK01665499 | 용도설명서 및 상세규격서 HWP | 우선 확인 1개 | 그래픽카드의 정량적 기술 요구규격 |

모든 7개 파일이 파서 success를 반환했다. 관측 기록은 파싱 결과의 관련 구간을
검토한 것으로, 원본 전체의 시각적 대조·이중 검수·부재 증명까지 끝낸 정답 라벨이
아니다. 선정·미선정 파일을 함께 확인하는 절차를 수행했지만 이 2건으로 품목별
정밀도·회수율 80%를 입증하지 않는다.

기존 개발 자료 20건·84개 첨부의 결과는 우선 확인 17개·추가 확인 5개·수동 확인
62개였다. 추가 표본은 우선 확인 2개·수동 확인 5개였다. 이 값은 처리 우선순위
분포이며 규격서 정답 개수나 품질 지표가 아니다.

## 5 파서 적합성의 현재 한계

- HWP/HWPX에서 반환된 pageNumber가 정확한 원본 페이지 위치라는 보장은 없다. 추가 표본의 같은 공고문은 HWP pageCount 8, PDF pageCount 4를 반환했다.
- 기존 5개 중 HWP/HWPX bbox 반환은 0개다. 문서 내 블록·셀 경로와 실제 페이지 좌표를 구분해야 한다.
- 병합 span과 placeholder가 함께 있는 IR을 그대로 행 길이로 더하면 잘못된 표가 될 수 있다. adapter에서 실제 병합·점유 규약을 검증해야 한다.
- PDF 일부에는 HIDDEN_TEXT_FILTERED 경고가 있었다. 제거된 머리글·바닥글이 요구조건과 무관하다는 보장은 별도 확인이 필요하다.
- PDF 텍스트 파싱은 성공했으나 optional canvas 미설치 경고가 있었다. 렌더링·이미지·OCR는 끄거나 실행하지 않았으며 검증 범위가 아니다.
- 색상으로 필수조건을 표시한 문서가 있다. Markdown만으로 그 의미가 보존됐다고 판단하지 않는다.
- DOCX·XLSX·스캔 PDF·암호화·손상 문서는 이번 실험에 없다.

따라서 현재 결론은 **kordoc이 이 표본에서 본문과 표 IR을 반환해 후속 설계의
근거로 쓸 수 있다**는 것이다. 공통 Document JSON adapter와 전체 파싱 모듈의
완료를 뜻하지 않는다.

## 6 구현·자료 위치와 재현

- 기존 원본: `.artifacts/procurement_specifications/computer_server/`
- 실험 루트: `.artifacts/procurement_specifications/server_validation/`
- `parser_probe/package-lock.json`: 설치한 파서·의존성 고정. 저장소 의존성에는 추가하지 않음
- `parser_probe/probe.mjs`: 로컬 원본 순차 파싱, SHA-256 확인, 원시 JSON·Markdown·집계 보존
- `parsed/`, `review_parsed/`: 각각 기존 5개와 추가 7개의 파서 출력
- `sample_query.sql`, `new_sample.jsonl`: 추가 표본의 읽기 전용 조회와 메타데이터
- `download_summary.json`: 전송 예산·실제 용량·hash·실패 상태
- `metadata_priorities.json`, `metadata_summary.json`: 20건·추가 2건의 우선순위 결과
- `content_review_observations.json`: 내용 관측과 검토 범위. gold label로 표시하지 않음
- `hwpx_structure_comparison.json`: 원본 XML과 반환 IR의 표·셀 집계 비교

```bash
uv run --locked --project backend pytest \
  backend/tests/integrations/data_operations/domains/public_procurement/specification_intelligence

node .artifacts/procurement_specifications/server_validation/parser_probe/probe.mjs
```

코드 동작과 형식 계약은 설치한 패키지와
[공식 API 소스](https://github.com/chrisryugj/kordoc/blob/main/src/index.ts),
[공식 타입 정의](https://github.com/chrisryugj/kordoc/blob/main/src/types.ts)를 대조했다.
공식 소스의 main은 변할 수 있으므로 이번 실행의 기준은 로컬 lockfile의 4.22.15다.

## 7 다음 작업과 완료 조건

현재는 사용자 지시에 따라 **kordoc을 고정하고 규격서 선별 로직의 적정성**을
평가한다. 위 파싱 한계는 기록하되 파서 교체·전체 adapter 구현을 다음 작업의
선행 조건으로 삼지 않는다.

1. 같은 kordoc 버전·옵션으로 서버 평가 표본의 선정·미선정 첨부를 파싱한다.
2. 업체 기입란·예시 규격·참조와 실제 발주 요구규격을 구분해 내용 상태·대상 품목·근거 위치를 검수한다.
3. 고정된 선정 정책에 대해 오선정·누락·미확인을 분리하고 정밀도·회수율·비용을 측정한다.
4. 개발 표본의 실제 오류를 근거로 공통 선별 규칙을 개선하고 독립 표본에서 재평가한다.

공통 Document JSON·adapter와 두 번째 품목 확장은 후속 설계다. 현재 선별 정책과
평가 계약의 기준은 [선별 로직 문서](document_identification.md)를 따른다.

현재 통과한 검증은 공통 우선순위 테스트 22개, Pipeline 전체 **177 passed,
16 skipped**다. 기존 Prefect Mermaid 경고 1개가 있으며 생략한 통합 검증·운영 배포·
파싱 완전성·실제 회수율은 이 테스트 결과에 포함하지 않는다.
