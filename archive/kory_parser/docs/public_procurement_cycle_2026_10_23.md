# 공고 첨부문서 개선 사이클: 2026-10-23

Kory Parser 0.9.1을 기준으로 실제 공고 첨부를 표본 추출하고, 원문에서 확인한 PDF 중복
문제를 수정했다. 품질·출력 보존·시간·테스트 수용 기준을 통과한 뒤에만 0.9.2를 반영했다.
활성 Platform·Pipelines·MCP와 서비스 배포는 변경하지 않았다.

## 표본과 조건

Teoria Data DB에 수집된 2026-10-01 이상, 2026-10-24 미만 공고를 현재 시각까지 조회했다.
물품·용역·공사·외자·기타에서 hash 순서로 각 6개 공고를 선택해 30개 공고, 첨부 후보
115개를 확보했다. 파일 형식·업무유형 순환, 공고차수당 최대 3개, 바이트 중복 제거로
실제 첨부 30개를 내려받았다. HTTP 실패 1건도 시도 기록에 남겼다.

| 실제 형식 | 수 |
|---|---:|
| HWP | 12 |
| HWPX | 7 |
| PDF | 4 |
| DOCX | 2 |
| XLSX | 3 |
| XLS | 1 |
| JPEG | 1 |

기관·업무유형 family 단위의 개발 17개, 분리 검증 13개다. 정답은 XML 원문에서 추출한
부분 검사와 Codex가 원문 PDF 렌더를 시각 확인한 구조 검사로 만들었다. 별도 사람 감수나
전체 문서 정답 검수를 주장하지 않는다. 원문 기반 부분 검사는 13개 문서에 적용했다.
검토한 검증 문서는 앞으로 회귀 자료이며 새 블라인드 평가로 재사용하지 않는다.

비교 대상은 고정한 Kory 0.9.1, 수정 후보 0.9.2, 설치된 kordoc 4.22.15다. 동일 원문
SHA-256과 OCR·이미지 추출 OFF 조건을 사용했다. 입력 바이트를 미리 읽고 warm-up 1회,
측정 3회 중앙값을 기록했다. parse 시간에 프로세스 시작과 파일 읽기는 포함하지 않았다.

## 확인한 문제와 변경

개발 표본 `R26BK01784919:000`의 첨부 2번은 7쪽짜리 내역서다. 원문에는 물리 쪽마다
13열의 표 하나가 있다. 처음 6쪽은 22행, 마지막은 3행이다. 기존 파서는 실제 셀 경계와
여러 셀을 덮는 큰 clipping 영역을 각각 표로 보아, 2~6쪽의 본문을 추가 표에 중복했다.

`pdf_geometry.distinct_grids`에서 여러 실제 ruled cell을 가로지르는 단일 clipping frame을
중복 후보에서 제외했다. 한 셀 안의 실제 중첩 표와 다른 바깥 영역은 보존한다. 표 바깥의
글자는 일반 문단 추출 대상으로 남는다. 공고번호·파일 hash·원문 문구로 분기하지 않는다.
기하 회귀 테스트가 기존 0.9.1에서는 실패하고 후보에서 통과하는 것을 확인했다.

## 수치 비교

| 지표 | Kory 0.9.1 | Kory 0.9.2 | kordoc 4.22.15 |
|---|---:|---:|---:|
| 실행 성공 | 29/30 | 29/30 | 29/30 |
| 문제 PDF의 쪽별 표 개수 일치 | 2/7 | **7/7** | 3/7 |
| 문제 PDF의 쪽별 표 개수·행열 일치 | 2/7 | **7/7** | 0/7 |
| XML 원문 표 개수 일치 문서 | 9/9 | 9/9 | 8/9 |
| XML 원문 조각 존재 검사 | 5,434/5,435 | 5,434/5,435 | 5,434/5,435 |
| XLSX cached 셀 값 의미 일치 | 2,570/2,570 | 2,570/2,570 | 2,566/2,570 |
| 공통 성공 29개: 문서별 중앙시간 합 | 3.168012초 | **2.819083초** | 3.951111초 |
| 문제 PDF 중앙시간 | 0.344576초 | **0.269627초** | 0.151730초 |

7쪽 검사는 하나의 PDF에 대한 부분 구조 검사이며, 7개의 독립 문서에 대한 정확도가 아니다.
JPEG의 실패는 세 구현 모두 OCR을 끈 조건의 `NEEDS_OCR`였다.
원문 조각 존재율은 본문 전체 정확도가 아니고 cached 값 의미 일치는 셀 표시 형식 정확도가 아니다.

문제 PDF의 불필요한 추가 표는 5개에서 0개로 줄었다. 이 문서의 정규화 본문 길이는
3,496자에서 1,958자로 줄었지만, 길이 감소 자체를 정확도 점수로 사용하지 않았다.
원문으로 확인한 쪽별 표 개수·행열의 통과율은 28.57%에서 100%로, **71.43%p 상승**했다.

이번 표본의 중앙시간 합은 기존 대비 **11.01% 감소**, kordoc 대비 **28.65% 감소**했다.
문제 PDF만 보면 기존 대비 **21.75% 감소**했지만, 이 PDF에서는 kordoc이 더 빨랐다.
모든 문서나 환경에서 Kory가 더 빠르다는 의미는 아니다.

kordoc 대비 평균 문자 multiset F1은 0.989674에서 0.999371로 증가했다. 이는 reference
일치도이며 원문 독립 정확도가 아니다. 정규화 본문 완전 일치는 20/29, 전체 표 격자 일치는
26/29로 기존과 동일했다. 원문 구조를 더 잘 복원해도 kordoc과의 구조 일치는 늘지 않을 수 있다.

## 수용과 회귀

- 전체 단위·평가 테스트 191개가 통과했다.
- 새 표본에서 목표 PDF 이외의 29개 출력은 `parser_version`을 제외하고 동일했다.
- 기존 보관 실문서 106개를 후보로 다시 실행해 출력이 버전 표기만 제외하고 모두 동일했다.
- 원문 부분 검사에 퇴행이 없었다.
- 공통 성공 문서의 시간 합이 기존 대비 5% 넘게 증가하면 거절하도록 했다.
- 개별 문서가 15%와 10 ms를 모두 초과해 느려진 경우 별도로 5회 측정했다.

초기 HWP 한 건과 XLSX 한 건의 지연 경고는 확인 측정에서 기준을 초과하지 않았다.
HWP 확인 중앙값은 0.015167→0.015624초, XLSX는 0.170082→0.193384초였다.
XLSX는 확인 측정에도 약 13.7% 느리게 남았다. 허용 기준 안이라는 뜻이며 모든 문서가
빨라졌다고 해석하지 않는다. 최초 측정은 유지했고 확인 측정으로 시간 합을 덮어쓰지 않았다.
메모리 사용량과 OCR 정확도는 이번에 측정하지 않았다.

후보를 별도 snapshot으로 보관하고 기존 소스를 복구한 상태에서 gate를 실행했다.
gate가 후보 hash·기준 hash·원문 검사·기존 회귀·테스트·시간 조건을 확인한 뒤
`accepted: true`, `applied: true`를 기록하고 두 파서 소스 파일만 반영했다.
commit/push나 운영 배포는 수행하지 않았다.
