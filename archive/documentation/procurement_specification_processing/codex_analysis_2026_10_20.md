## 5단계 구성요소 식별 시험

같은 native JSON과 저장된 3·4단계 결과를 읽고 Codex가 5단계 제안을 작성했다.
별도 모델 호출은 없으며 구성요소 자동 추출 알고리즘을 실행한 결과가 아니다.
제안은 신규 `component_stage_v1/` 폴더에 보존하고 독립 CLI로 검증·저장했다.

| 품목 | 대상 후보 수 | 주요 대상 |
|---|---:|---|
| 서버 | 12 | 본체·CPU·메모리·섀시·PSU·SSD·베이·RAID·NIC·GPU 확장 대상·GPU 키트·설치 소프트웨어 |
| DAS | 5 | 인클로저·HDD·PSU·외장 RAID 어댑터·관리 소프트웨어 |
| 랙 | 4 | 캐비닛·KVM·LCD 콘솔·멀티 콘센트 |

기존 초기 분석의 19개 평면 후보를 그대로 옮기지 않고 본체와 GPU 키트를 구분해
총 21개 대상 후보로 작성했다. 이 목록에는 물리 부품 외에 설치 환경·확장 대상도 포함된다.
관계 15개는 `HAS_PART` 12개, `SUPPORTS_EXPANSION` 1개,
`REQUIRES_SOFTWARE` 2개다. 원문 제목 그룹 5개와 품목 전체 구간 5개도 별도로 보존했다.

주요 판단은 다음과 같다.

- 서버 PSU와 DAS PSU는 같은 유형의 별도 대상이다.
- GPU는 현재 납품 부품이 아니라 확장 지원 대상이며 설치 키트는 별도 포함 대상이다.
- ‘형상 및 전원’, ‘네트워크·확장 및 소프트웨어’는 원문 그룹으로 유지한다.
- CPU당 코어 조건과 시스템 총 코어 구간을 구분하고 시스템 인증은 서버 전체에 연결했다.
- DAS RAID 어댑터의 물리 설치 위치는 확정하지 않아 인클로저의 부품 관계를 만들지 않았다.
- KVM과 LCD 콘솔은 기능별 후보로 나누되 일체형 여부·각각의 수량·캐비닛 내부 설치는 확정하지 않았다.

`component_submission.json`, `component_result.json`과 두 JSON Schema가 산출물이다.
`prepare_submission.py`는 Codex가 작성한 제안을 저장하는 실험 스크립트이며 자동 추출기가 아니다.
계약 검증 결과는 `passed`, 의미 검토는 `pending`, 유형 매핑은 `NOT_ATTEMPTED`다.
미배정 품목 노드 26개, 공통 노드 43개, 선행 미배정 텍스트 11개와 이미지 미확인 1개를
그대로 보존했다. 제목·내역표·용도 일부와 공통 조건도 있어 미배정 수는 추출 오류율이 아니다.
후속 요구조건 추출은 이 범위들을 확인해야 한다.
