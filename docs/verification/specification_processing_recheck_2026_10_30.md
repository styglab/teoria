### 2026-11-03 반복 개선 스킬·평가 수명주기 보완

기존 스킬과 평가 CLI에 로컬 원본 discover/status, 분류 없는 신규 원본의 그룹별 개발/검증 분할,

inconclusive로 유지한다. 테스트 실패/회귀의 rejected는 다른 판정 제한으로 덮지 않는다.

기존 샘플 10개의 바이트·원문 대조 사례(엔티티 26, 관계 2, 요구조건 13)를 고정한

GLiNER2 2.1.0은 fastino/gliner2-multi-v1을 CPU 4스레드로 실행했다. 초기 fine-tuning은

순수 효과를 분리한 실험이나 반복 측정의 통계적 우열로 해석하지 않는다.

Docling은 한국어 RapidOCR/onnxruntime 설정에서 PDF 3·XLSX 3·DOCX 1, 총 7개 변환에
성공했고 HWP 1·HWPX 2, 총 3개는 직접 미지원이었다. 최초 OCR 런타임 미설치는 보완 후
재실행했으며 preflight 결과를 최종 결과에 섞지 않았다. 유제품의 예정수량 병합 헤더와
1동/8동·143000/92000/51000 셀의 행/열/병합 폭이 보존됐다. 서버 XLSX도 제목·상세 사양
셀을 보존했다. LCMS의 표 셀 41개, 초음파의 표 셀 48개에는 PDF bbox가 있었다.
셀/노드 수가 다른 것은 성공률이나 추출 정확도 차이로 계산하지 않았다. 가구 XLSX의
EMF 그림 미변환 경고는 남아 있어 변환 success를 모든 시각 정보 보존으로 간주하지 않는다.

연결 preflight에서 Docling Graph의 auto/dense schema와 Codex의 strict JSON 계약이
충돌했다. 이 실패를 모델의 추출 정확도 저하로 귀속하지 않았다. 최종 비교는 direct 계약,

초기 auto가 direct로 처리해 실제 완료한 3문서는 동일 출력으로 유지했다.
LangExtract는 원문 순서에 맞춘 별도 중립 예시와 UnicodeTokenizer로 10개를 다시
실행했다. 초기 예시 정렬 경고가 있던 결과는 제외했다. extraction_passes=1,

문자 위치 미정렬 결과는 라이브러리 안내대로 제외하되 개수를 별도로 기록한다.

GLiNER2는 구조 직렬화의 행/열 숫자까지 값 후보로 잡아, 동일 원문 노드의 순수 텍스트
