# Market context runtime

이 패키지는 조달 원천을 읽어 기관·업체·공고 관계를 계산한다. DB 접근과
판정 정책을 섞지 않는 것을 기본 원칙으로 한다.

## 모듈

- `processor.py`: Capability 진입점, 원천 오류 변환과 응답 orchestration
- `queries/`: 기능별 SQL 문장
- `readers/`: Data DB 접근 경계
- `attention.py`: 주목할 업체의 계약 시점 상태, 선정 사유, 다양성 및 정렬 정책
- `related_projects.py`: 관련 사업의 복합 필터, 정렬, 페이지네이션 정책
- `similarity.py`: 제목·사업유형·업무분야·금액 유사도 순수 정책

새 판정 규칙은 가능한 한 순수 정책 모듈에 추가한다. 정책 모듈은 Registry,
DB connection 또는 Runtime cache를 직접 참조하지 않는다. `processor.py`는
정규화된 행을 정책 함수에 전달하고 결과를 Capability 응답에 넣는 역할만 한다.

## 변하지 않아야 하는 기준

- 계약과 업체를 먼저 고유 사건으로 병합한 뒤 필터와 페이지네이션을 적용한다.
- 신규·재진입 및 반복 판정은 각 계약일 직전 이력만 사용한다.
- 공동계약의 상태는 업체별로 판정하되 목록 건수는 계약 사건 기준이다.
- 사용자 표시 사유와 내부 전체 근거를 분리한다.
- 상대적인 상위 25% 계약은 절대적인 `대형 계약`으로 표현하지 않는다.
- 판정 임계값과 정렬 우선순위는 응답의 basis에 함께 반환한다.

## 변경 순서

1. 정책 모듈의 단위 테스트를 먼저 추가한다.
2. Capability 회귀 테스트로 응답 계약을 확인한다.
3. Registry 입력 또는 의미 계약이 바뀌면 버전과 release를 갱신한다.
4. 운영 공고로 고유 사건 수, 정렬, 캐시 결과를 검산한다.
