# FormatID 문서 탐색·비교 배포 — 2026-10-31

## 변경

첫 화면을 실행 목록에서 분류별 규격서 목록으로 변경했다. 파일명·공고번호 검색, 최근 처리 상태·기간 필터,
서버 페이지 조회를 제공한다. 동일 분류·공고·원문 checksum의 재처리는 한 항목으로 묶고,
내용이 다른 원문은 별도 버전으로 제공한다. 최근 처리 실패·진행 상태와 이전 정상 결과를 별도로 표시한다.
목록 쿼리는 DB 메타데이터만 읽고 문서 본문은 객체 저장소에 유지한다.

상세는 파일명을 제목으로 사용하며 처리 이력과 적용 기준은 필요할 때 연다. 확인된 구성 관계는
기본 트리로 제공하고, 구성 관계가 없으면 목록을 사용한다. 속성이 있는 대상을 우선 선택한다.
키보드 초점 이동과 대상 선택, 관계 펼치기를 구분한다. 기본은 트리·상세의 2열이고 원문 근거를
열 때만 패널이 추가된다. 표준 미매핑은 추출·귀속·근거 미해결 건수와 구별한다.
추출용 표준 초안을 Published Ontology로 표시하지 않는다.

같은 분류의 문서 2–4개를 비교한다. 표준 스냅샷·대상 개념·속성·역할·범위·단위가 확인된
동일 기준의 값만 같은 행에 배치한다. 다른 구성품의 관찰을 합산하지 않고 연산자·조건을 보존한다.
서로 다른 추출 표준의 로컬 식별자는 동일 개념으로 추정하지 않는다. 각 값에서 문서 원문으로 이동한다.

문서별 projection을 완료 checkpoint 전에 객체 저장소에 저장하고 참조만 DB에 등록하는 Task를 추가했다.
새 migration `104_specification_document_catalog.sql`로 입력 메타데이터를 보관한다.
기존 적용 migration은 변경하지 않았다. 기존 실행별 링크와 입력·Flow 실행 경로도 제공한다.

## 검증

- 프런트엔드 22개 파일·91개 테스트 및 TypeScript·Vite 프로덕션 빌드 통과.
- 전체 백엔드 857개 통과·84개 환경 의존 검사 생략. 최종 SQL 변경 후 소유 기능 검사 9개 통과·1개 격리 DB 검사 별도 실행.
- 임시 PostgreSQL DB에서 migration과 쿼리를 실행했다. 버전·공고 분리, 재처리 실패 시 이전 정상 결과,
  진행/실패 실행의 중간 산출물을 최종 결과로 제공하지 않는 정책, 필터·이력·빈 페이지를 검증했다.
  임시 DB는 검사 후 삭제했다.
- 문서 검사 9개, 기본 Compose 및 실제 모듈 조합의 config 검사 통과.
- 실제 저장 결과를 사용하는 배포 게이트웨이에서 Chromium으로 분류·문서 목록, 상세 2열,
  원문 패널, 처리 이력, 문서 2개 비교, 390px 모바일을 확인했다.
  이 확인은 추출 의미의 정확도 평가가 아니다. 비교 정렬·반복 값·표준/범위 분리는 컴포넌트 검사로 검증했다.

## 실제 배포 및 저장소 제약

Compose `teoria`의 API·의미 제어 프로세스·메타데이터 Worker·규격서 Worker·웹을 갱신했다.
Worker 교체 전 실행 중인 Prefect Flow가 없음을 확인했다. 운영 DB에서 migration 104 적용을 확인했다.
기존 실행 8개의 문서별 색인을 보강했다. 나머지 7개 실행은 현재 허용된 저장소에서 접근할 수 없는
과거 산출물 참조여서 보강하지 않았다. 저장소 경계를 완화하거나 원문 내용을 추정하지 않았다.
이 과거 참조를 선택하면 결과 조회가 실패할 수 있으며, 복구하려면 원래 저장소의 산출물이 필요하다.

최종 이미지·서비스 검증과 정리 결과는 배포 상태의 `document_catalog_after.json`,
`document_catalog_verification.json`과 아래 기록을 따른다.

최종 배포에서 22개 서비스 모두 실행 중이며 healthcheck가 있는 서비스는 모두 healthy였다.
인증된 Admin API·선택 모듈 연결 검사를 통과했고 제공된 JS/CSS가 검증한 로컬 빌드와
동일한 checksum임을 확인했다. Chromium 결과는 분류 2개·규격서 33개 목록, 문서 상세의
기본 2열·요청 시 원문 패널, 문서 2개 비교, 모바일 가로 넘침 없음이었다.
브라우저 예외·서버 5xx·화면 점검 중 쓰기 API 요청은 각각 0건이었다.

| 서비스 | 최종 이미지 ID 앞 12자리 |
|---|---|
| Admin API 및 같은 이미지의 제어/메타데이터 Worker | `2670d514f875` |
| 규격서 Worker | `273a6210b88e` |
| 웹 게이트웨이 | `26645f7b9407` |

교체 전 컨테이너가 남아 있지 않음을 확인했다. 모든 프로젝트의 실행·중지 컨테이너와
다른 배포 상태에서 참조하지 않으며 별도 태그가 없는 이전 이미지 6개를 강제 옵션 없이 삭제했다.
관련 없는 서비스와 다른 프로젝트의 이미지는 유지했다. 배포 상태의 이미지 참조도 갱신했다.
삭제한 이전 이미지는 로컬 rollback 대상으로 남아 있지 않다.
