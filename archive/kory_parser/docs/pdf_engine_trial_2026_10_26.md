# PDF 엔진 대체 실험 — 2026-10-26

**미채택. 현재 Kory Parser의 PyMuPDF 기본 엔진과 의존성·잠금 파일은 유지했다.**
속도 저하가 없을 때만 교체한다는 사용자 조건으로 `pdfplumber + pypdfium2` 후보를
격리 적용했다. 이 후보는 PDF 처리시간이 기존의 **3.31배**이고
기능 보존 검사도 실패했다. 이번 결과는 이 대체 구현에 대한 판정이며 다른 구현의 성능까지
일반화하지 않는다.

## 구현과 비교 조건

- 현재 Kory Parser 0.9.15를 baseline으로 고정했다. 기존 미커밋 변경도 snapshot에 포함했다.
- 후보는 `pdf_native.py`를 pdfplumber/pdfminer 기반 문자·선·사각형·명시적 직사각형 clip
  추출로 대체하고, `ocr.py`의 페이지 렌더링을 PDFium으로 바꿨다. 기존 표·문단 조립은 유지했다.
- 기존 테스트와 평가기·정답·정책·공개 옵션은 변경하지 않았다. 시험에서만 기존
  `pdf_backend=pymupdf` 옵션 표기를 유지하고 후보 내부의 기초 추출을 교체했다.
  대체 후보는 MuPDF로 fallback하지 않는다. 이는 배포 가능한 다중 엔진 API가 아니다.
- baseline·candidate는 같은 Python 3.12.13 환경에서 실행했다.
  PyMuPDF 1.27.2.3, pdfplumber 0.11.10,
  pdfminer.six 20260107, pypdfium2 5.14.0를 사용했다.
- 고정 회귀셋의 PDF 57개와 신규 공고 첨부 12개를 합친 69개를 비교했다.
  총 PDF 59개이며 나머지 10개는 HWP·HWPX·DOCX다. 신규 표본은 개발 8개·검증 4개이며
  신규 PDF 2개는 모두 개발 split이다. 새로운 PDF 양식에 대한 블라인드 검증 주장은 하지 않는다.
- 동일 원문 hash와 옵션으로 baseline·candidate·kordoc 4.22.15를 비교했다.
  문서별 warm-up 1회 후 3회 중앙값이며 시작·파일 읽기 시간은 제외했다.
  문서별 실행 순서를 교대했다. OCR·이미지 본문 추출은 끄고 번호 구조 복원은 켰다.

## 속도와 처리 성공

| 지표 | 기존 PyMuPDF | 대체 후보 |
|---|---:|---:|
| PDF 처리 성공 | 56/59 | 56/59 |
| 공통 성공 PDF 중앙값 합 | 30.558초 | 101.051초 |
| 전체 69개 처리 성공 | 66/69 | 66/69 |
| 전체 공통 성공 문서 중앙값 합 | 31.112초 | 101.574초 |

PDF 문서별 시간 배율의 중앙값은 4.02배다.
실패한 PDF 3개는 두 구현 모두 동일하게 `NEEDS_OCR` 2개·`ENCRYPTED` 1개이며,
이들을 성공 문서 시간 합에 넣지 않았다. 실행 실패나 표본을 숨겨서 분모를 바꾸지 않았다.

15%와 10 ms를 모두 초과한 지연 경고 55개를 동일 snapshot으로
5회 재측정했다. 55개에서 같은 지연 기준을 재차 초과했다.
확인 대상 공통 성공 55개의 중앙값 합은 기존 25.361초,
후보 100.005초로 **3.94배**다.
확인 대상은 지연 경고 문서만 모은 집합이므로 전체 59개와 구분한다.
첫 측정과 확인 측정은 모두 보존했다.

## 기능과 품질

기존 테스트는 **314개 통과**했다. 후보는 기존 테스트 **298개 통과·16개 실패**,
추가한 MuPDF 없는 파싱·PDFium OCR 렌더링 검사 2개 통과다.
실패 중 10개는 MuPDF 연결·설치 방식에 의존하는 검사다. 나머지 6개는 다음 공개 동작 차이다.

- 회전된 여백 텍스트가 최종 출력에서 누락되는 사례 1개.
- 이미지 요청 시 복원 가능한 PNG 본문·MIME을 반환하지 못하는 사례 1개.
- 회전 0/90/180/270도에서 기존 좌표 계약과 달라지는 사례 4개.

후보의 이미지 인코딩과 폰트 복원 등은 완성된 동등 대체가 아니다. 위 실패를
라이브러리 자체의 한계라고 단정하지 않는다. 속도 저하와 기능 차이를 확인한 뒤
이 후보를 더 다듬어 기본 엔진으로 승격하지 않았다.

공통 성공 PDF 56개 중 정규화 본문 전체 일치는 34개,
표 격자 일치는 47개, 표 격자·셀 내용 일치는 45개다.
평균 문자 multiset F1은 0.999752이다.
이는 **기존 출력과의 일치도**이며 원문 정확도가 아니다. 높은 문자 일치도로 읽기 순서·표 구조
변화를 상쇄하지 않는다. benchmark의 비PDF 10개 출력은 모두 동일했다.

원본 XML 또는 Codex가 시각 확인한 PDF에 근거한 부분 검사는 8개 문서다.
검사 개선 0개·퇴행 0개였다.
2403개 원문 텍스트 조각 중 양쪽 모두 2400개를 보존했고 XML 표 개수는 5/5였다.
원문에서 7행·4열 표 1개가 보이는 신규 PDF 첫 페이지는 두 Kory 구현 모두
표 격자를 출력하지 못했다. 2행·4열 및 3행·4열 표는 각각 다른 페이지의 표이며,
첫 페이지 표가 이 두 조각으로 분리됐다는 종전 설명을 정정한다.
첫 페이지의 셀 글자는 이미지이며, 후속 [이미지 표 복원 후보 검증](pdf_image_tables_2026_10_26.md)에서
텍스트 없는 격자를 버리는 원인을 확인했다. 이 실험의 원문 정답과 측정값은 변경하지 않았다.
부분 검사를 전체 PDF 정확도나 사람의 독립 검토로 해석하지 않는다.

고정 회귀셋 160개도 재실행했다. 버전 표기를 제외한 전체 출력 일치는
**107/160개**다.
비PDF 103개는 전부 동일했고, PDF 57개 중 4개가 동일했다. 상세 비교는 로컬
`regression/report.json`과 `comparison_summary.json`에 있다.

## 판정과 재현 자료

기존 gate는 미채택이며 `applied=false`다. 이 gate는 품질 개선도 요구하므로
개선 없음 사유도 함께 기록된다. 이번 미채택은 속도·기능 보존 실패만으로도 확정된다.
활성 Platform·Pipeline·배포에는 연결하지 않았다.

로컬 자료는 `.artifacts/pdf_engine_trial_2026_10_26/`에 있다.

- `baseline/`, `candidate/`, `candidate.patch`: 고정 소스와 추가 검사.
- `protocol.json`, `environment.json`, `engine_requirements.txt`: 구현과 환경.
- `comparison_manifest.json`, `sample/cycle_manifest.json`: 입력 hash·신규 표본 provenance.
- `benchmark/benchmark.json`, `timing_confirmation/benchmark.json`: 3회·5회 측정.
- `comparison_summary.json`, `quality.json`, `source_labels.json`: 출력 비교와 원문 부분 검사.
- `regression/report.json`, `acceptance/acceptance.json`, `report/summary.json`: 회귀·판정·요약.

자료는 Git에 추가하지 않았다. 파서의 기존 `.venv`를 locked 환경으로 준비한 뒤
`prepare_environment.py`로 격리 환경을 복원할 수 있다. 재측정에는 새 output 경로를 쓰며
기존 결과·manifest·공통 corpus history를 덮어쓰지 않는다.

기본 report cleanup과 추가 정리로 229,810,176 bytes를 제거했고,
이 실험 디렉터리에 26,705,920 bytes를 보존했다.
고정 회귀 원문·사용 이력·선택한 원문 근거·문제 사례·고정 소스·측정값은 유지하고,
일반 성공 표본의 중복 출력·캐시·격리 설치 환경은 제거했다.

OCR 추론 정확도·OCR 전체 지연·메모리·동시 요청 처리량은 측정하지 않았다.
OCR 렌더링은 추가 검사로 페이지·크기·색상 형식만 확인했다.
공유 호스트의 warm parse 결과이며 실제 서비스의 지연 보장은 아니다.
