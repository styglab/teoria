# 0.9.14 수동 번호 계층 복원

후속 0.9.15에서는 동일한 복원 알고리즘을 기본으로 활성화했다. 아래 수치는0.9.14의
옵션 활성화 평가 기록이다. 0.9.15는 `parse(path)`로 사용하고, 기존 출력은
`ParseOptions(recover_numbered_structure=False)` 또는 `--no-numbered-structure`로 선택한다.

직접 입력한 번호가 HWPX의 제목/목록 속성 없이 일반 문단으로 저장된 경우를 개선했다.
`ParseOptions(recover_numbered_structure=True)` 또는 CLI `--numbered-structure`로 사용한다.
기존 출력 호환성을 위해 기본값은 꺼져 있으며 HWP·PDF·DOCX에는 이번 복원을 적용하지 않는다.

본문의 로마 숫자 구획 반복과 원문 앞쪽 공백으로 깊이를 확인하고 평평한 `blocks`에
`type="list"`, `level`을 표시한다. 기존 제목/목록 속성을 우선하고 원문 텍스트·span·source를
보존한다. `Ⅲ. 성능 및 규격 → 1. 컴퓨터 서버 → 가. 본체 / 나. CPU`에서 본체와 CPU는
같은 깊이다. 업무 단어로 부품 포함 관계를 추측하지 않는다.

목차 제목의 쪽 번호뿐 아니라 하위 항목의 쪽 번호도 확인해 본문 계층과 구별한다.
먼 옛 구획의 번호를 뒤 문단에 이어 붙이지 않으며, 같은 깊이의 로마 숫자 앞쪽 공백이
조금 다른 경우도 형제 구획으로 복원한다. 한 문단에 여러 줄이 있으면 첫 줄의 번호만
문단 깊이로 표시하고 내부 하위 번호를 별도 블록으로 분리하지 않는다.

## 검증 범위

최종 비교는 새 공고12개(개발8/기관별 검증4)와 기존 개발·회귀 문서21개, 총33개다.
33개 모두 기존 Kory·후보·고정 kordoc4.22.15에서 처리됐다. 원문 구조 지표는 이 중
개선 대상3개와 목차 오분류 대조1개의 **선별 검사205개**이며 전체 문서 정확도가 아니다.
일반 문단 대조82개는 보존했고, 수동 번호123개의 문단 종류·깊이를 추가 복원했다.

| 원문 기준 검사 | Kory0.9.13 | Kory0.9.14 옵션 사용 | kordoc4.22.15 |
|---|---:|---:|---:|
| 선별 문단 종류·깊이와 일반 문단 대조 | 82/205 | 205/205 | 82/205 |
| 원문 XML 텍스트 조각 존재 | 3638/3638 | 3638/3638 | 3638/3638 |
| 원문 XML 표 개수 | 16/16 | 16/16 | 16/16 |

동일 바이트·OCR/이미지 끔·새 복원 옵션 켬으로 비교했다. 기존 알고리즘의 기준판에는
동일 옵션을 받을 수 있는 선언만 추가했고 복원 동작은 넣지 않았다. kordoc에는 같은
복원 옵션이 없으므로 자체 동작을 비교했다. 꼬리의 빈 문단/그림 블록 수 차이를 피하려고
문단 위치 대신 원문 텍스트와 반복 순번으로 대응시켰다.

기존 고정 회귀160개는 기본 옵션에서 버전 표시를 제외한 출력이 동일했다. 원래 seed8개와
수동 계층 전체 출력 계약4개를 합친12개 계약은 기존10/12에서 후보12/12로 개선됐다.
최초 최종 후보 측정의33개 warm 중앙값 합은 기존1.557819초, 후보1.566617초로 약0.6%
증가해1.05배 제한 이내였다. 5회 확인 측정도 별도로 보존했다. 원문 개별 검사에서의
퇴행은0개이며 표준 gate가 채택한 소스만 반영했다.

이전 후보의 넓은 문단 분류와 목차 범위 오류를 수정했고, 처음부터 고정한120개 구조
검사와 기존 테스트·정책은 바꾸지 않았다. 새 개발 문서의 추가 원문 검토에서 정답3개가
들여쓰기 있는 괄호 번호를 놓친 사실을 발견했다. 이전 정답을 보존하고 별도 corpus
정정으로 기록했다. 이 정정으로202/205가205/205가 된 부분은 파서 개선으로 세지 않으며,
위 표는 기존/후보/참조를 **동일한 정정 원문 기준**에서 비교한 결과다. 추가 검토한 개발
문서를 새 블라인드 검증으로 주장하지 않는다.

원문·정답·소스 snapshot·측정 hash와 비교 보고서는 로컬 `.artifacts/cycle_2026_10_26_003/`
아래에 보존한다. 전체 파싱 JSON, 다운로드 임시 복사본, 비교용 Node 설치와 오래된 wheel은
검증 후 정리한다. 고정 회귀 원문·문제 재현 자료와 사용 이력은 유지한다.
