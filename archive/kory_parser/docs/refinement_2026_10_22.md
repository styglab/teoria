# 0.9.1 배포 구성·진단·목차 개선

Git에 포함된 파일만으로 기본 테스트가 실행되도록 정리하고, 선택 목차 기능의 알려진
오탐과 반복 계산을 개선했다. 활성 Platform·Pipelines·MCP·배포에는 연결하지 않았다.

## 변경

- 파서 테스트는 `tests/`, 실험 도구 테스트 5개 파일은 Git 제외 대상인
  `verification/tests/`로 구분했다. 기본 테스트에 실험 자료나 평가 도구가 필요하지 않다.
- source distribution에서 `verification/`, `.artifacts/`, `.venv/`, `dist/`를 제외했다.
- 파일 형식을 확인한 뒤 해당 파서 모듈만 import한다. 형식 판별과 결과 구조는 유지한다.
- 예상치 못한 `KeyError`·`IndexError`를 `INTERNAL_ERROR`로 보고한다. 누락된 ZIP member와
  범위를 벗어난 XLSX shared-string 참조는 입력 오류로 검사해 `INVALID_FILE`로 반환한다.
  모든 종류의 내부 예외를 완전히 분류한다는 뜻은 아니다.
- ‘제안서 작성 서식/양식’ 뒤의 목차 후보는 쪽 번호나 본문 제목 연결 근거가 없으면
  제외한다. 같은 문맥에서도 실제 쪽 번호나 본문 연결이 있는 목차는 유지한다.
- 목차 구간에서 쪽 번호가 붙은 항목 수를 매번 다시 세지 않고 누적한다. 줄 파싱을
  재사용하고, 원문 줄을 두 번 생성하지 않으며, 반복 여백 판정도 한 번 계산한다.
  PDF의 쪽 번호 후보 검사는 끝이 숫자인 줄에 수행한다.

## 회귀 검증

기본 테스트 155개, 로컬의 실험 도구 테스트 27개를 별도로 실행한다. Git 포함 대상만
임시 디렉터리에 복사한 환경에서도 기본 155개가 통과했다. 기본 테스트 수가 줄어 보이는
이유는 과거 174개 중 평가 도구 테스트 27개를 분리하고, 실제 파서 테스트 8개를 추가했기 때문이다.

기존 106건의 기본 JSON은 버전 필드만 제외하고 모두 동일했다. 성공 101건뿐 아니라
OCR 필요 4건과 암호화 문서 1건도 비교했다. 목차 옵션을 켠 40건도 기존
문단·표·Markdown·원문 위치 부분이 모두 동일했다. 별도 목차 구조는 38건이 동일하며,
나머지 2건은 알려진 동일 기관 제안서 작성 양식의 HWPX/PDF 변환 쌍 오탐을 제거했다.

기존 선택 검사 항목의 목차 계층은 개발 문서 40/40개, 과거 분리 문서 27/36개로
유지했다. 새 표본의 일반화 정확도를 의미하지 않는다. 과거 분리 문서를 이번에는
회귀 자료로 사용했고, 해당 오류를 보고 규칙을 보완했다. 새로운 블라인드 검증은 하지 않았다.
목차 제목이 없는 개요와 원문 텍스트 층의 누락 문제는 이번 변경 범위에 포함하지 않았다.

## 시간 측정

이름 변경 직후 0.9.0 소스와 0.9.1을 독립 Python 프로세스로 번갈아 3회 실행했다.
두 버전 모두 목차 옵션을 켰고, 같은 문서·환경에서 측정했다. 아래 수치는 문서별
중앙값의 합이며 단일 batch 실행 시간이 아니다. import 비용과 JSON 직렬화를 포함한다.

| 기존 자료 묶음 | 문서 수 | 0.9.0 | 0.9.1 | 변화 |
|---|---:|---:|---:|---:|
| 개발 문서 | 20 | 16.542초 | 15.163초 | 약 8.3% 감소 |
| 과거 분리 문서 | 20 | 16.923초 | 16.248초 | 약 4.0% 감소 |

15% 및 10ms를 동시에 초과한 지연 경고는 최초 측정에서 각각 2건·1건이었다.
해당 3건을 다시 기존/신규 순서로 교차 5회 측정한 결과 경고 기준을 초과한 문서는
없었다. `general_04`는 0.186초→0.146초, `corpus_024`는 0.754초→0.664초,
`heldout_14`는 3.113초→3.231초였다. 마지막 문서는 약 3.8% 느리게 남았다.
추가 측정은 최초 경고를 확인하기 위한 것이며 최초 결과를 대체하거나 삭제하지 않는다.
전체 합이 줄었다고 모든 문서가 빨라졌거나 모든 환경에서 성능 저하가 없다고 판정하지 않는다.
원본 JavaScript kordoc과의 속도 우위를 측정한 결과도 아니다. 목차 옵션은 계속 기본 꺼짐이다.

긴 PDF인 `general_06` 한 건의 cProfile 진단에서 목차 복원 누적 시간은
0.0478초→0.0293초, 목차 구간 탐색은 0.0210초→0.0091초였다. 신규 버전의
native page 추출은 약 1.70초로 목차 복원보다 훨씬 컸다. 이 수치는 계측을 켠 단일 실행의
병목 진단이며 위 반복 시간 측정과 별도로 보관한다. 전체 PDF 속도를 더 높이려면
목차 규칙뿐 아니라 글자·기하 추출 비용을 살펴야 한다.

측정 소스는 `.artifacts/refinement_0_9_1/baseline/`, `timed_candidate/`에 보관했다.
최초 시간 측정 뒤 XLSX의 잘못된 shared-string 인덱스를 명시적으로 거르는 검사를 추가했다.
위 40개 입력은 HWP·HWPX·DOCX·PDF이며 그 XLSX 경로를 실행하지 않는다.
최종 소스는 `final_candidate/`에 별도로 보관했다. 원시 출력·반복 시간·추가 측정은
같은 `.artifacts/refinement_0_9_1/`에 남긴다. 이 실험 자료는 Git에서 제외한다.
