# 공공조달 분야 분류 기준과 확장 계획

이 문서는 Teoria의 공공조달 분석에서 물품·용역·공사의 분야를 표시하고 필터링하는
현재 기준과, 별도 기능으로 구축할 버전형 분류체계의 범위를 정의한다. 공공조달 고유
정책이며 Platform 공통 분류 추상화로 승격하지 않는다.

## 현재 제공 범위

현재 Runtime은 원천에서 확인되는 공식 분류를 사용하며, 서로 다른 업무구분의 분류를
하나의 임의 계층으로 합치지 않는다.

| 업무구분 | 현재 표시 단위 | 계층 탐색 |
|---|---|---|
| 물품 | 대표 구매대상물품의 `세부품명번호`·`세부품명` | 단일 단계 |
| 용역 | 공공조달 분류의 대분류·중분류·분류번호 | 원천 계층 사용 |
| 공사 | 공공조달 분류번호·분류명 | 단일 단계 |
| 외자·기타 | 원천에서 확인되는 공공조달 분류 | 확인된 범위만 제공 |

물품은 상위 물품분류 마스터를 아직 수집하지 않으므로 10자리 세부품명번호의 접두어를
잘라 대·중·소분류를 추정하지 않는다. 대표 구매대상물품을 공사 분야와 같은 단일
단계로 제공한다. 따라서 코드와 세부품명이 확인된 물품을 상위 분류가 없다는 이유로
`미분류`에 포함하지 않는다.

여러 구매대상물품이 있는 공고·계약은 원천 순번이 가장 앞선 품목을 대표 분야로
사용하고 전체 품목 목록은 상세 근거로 유지한다. 대표 분야 기준 집계가 전체 품목별
금액 배분을 의미하지는 않는다.

`work_type`은 물품·용역·공사를 구분하는 업무구분이며 분야가 아니다. 사업 대상 분야와
참가자격의 면허·업종도 서로 다른 의미이므로 같은 분류 축으로 합치지 않는다.

## 미분류 의미

현재 `미분류`는 해당 사건에서 사용할 수 있는 공식 분류번호와 분류명이 모두 없는
경우에만 사용한다. 다음 상태는 장기 분류체계 기능에서 분리해 제공한다.

- 원천 품목 코드 없음
- 원천 코드는 있으나 최신 분류로 매핑할 근거 없음
- 공식 변경 이력으로 최신 분류 매핑 완료

## 별도 분류체계 기능

향후 기능은 각 업무구분의 공식 분류체계와 변경 이력을 수집하고 과거 조달 데이터를
최신 분류체계로 정규화한다. 단순한 코드·명칭 사전이 아니라 다음 정보를 갖는 기간
유효 분류 레지스트리가 필요하다.

```text
procurement_classification
- taxonomy_id
- taxonomy_version
- work_type
- code
- name
- parent_code
- valid_from
- valid_to
- status

procurement_classification_transition
- taxonomy_id
- old_code
- new_code
- transition_type
- effective_date
- source_reference
```

원천 코드와 명칭은 덮어쓰지 않는다. 분석용 최신 분류를 별도로 계산하고 공식 변경
이력, 적용일과 근거를 함께 보존한다. 명칭 변경과 일대일 이동·통합은 최신 코드로
정규화할 수 있지만, 하나의 과거 코드가 여러 최신 코드로 분리된 경우에는 품목식별번호
등 추가 근거 없이 임의 배정하지 않는다.

## 목표 사용자 기준

장기 기능이 도입되면 분석과 필터의 기본값은 업무구분별 최신 공식 분류체계다. 계약
상세에서는 당시 원천 분류와 최신 정규화 분류를 함께 제공한다.

> 분야는 업무구분별 최신 공식 분류체계로 재분류하여 집계하며, 매핑 근거가 없는
> 사건은 별도로 표시합니다.

프로필 분석과 조달 활동 검색은 같은 정규화 결과를 사용해야 한다. 동일한 기간,
업무구분과 분야 필터가 서로 다른 계약 집합을 만들면 안 된다.

## 구현 경계

- 공식 분류 마스터·변경 이력의 지속 수집과 적재는 `pipelines/`가 소유한다.
- 분류체계와 원천 코드의 의미 계약은 공공조달 Domain Registry가 소유한다.
- Runtime은 Data DB에 적재된 분류와 매핑을 읽으며 운영 중 Provider 화면을 크롤링하지
  않는다.
- 입찰체크 등 클라이언트는 자체 분류 변환표를 만들지 않고 Runtime이 반환한 코드,
  명칭, 기준 version과 매핑 상태를 표시한다.

## 도입 전 완료 조건

1. 업무구분별 권위 분류원과 이용 조건을 확인한다.
2. 현재 마스터와 공식 신설·변경·삭제·분류이동 이력을 수집한다.
3. 원천 분류와 최신 정규화 분류를 함께 보존하는 Data DB migration을 추가한다.
4. 일대일 이동, 통합, 분할, 코드 없음과 매핑 불가 회귀 사례를 검증한다.
5. 프로필 분석과 조달 활동 검색이 동일한 분류 집합을 사용하는지 검증한다.
