# 규격서 80/20 자동 평가 결과

2026-10-20에 보존 규격서 20건으로 Codex 기반 자동화를 실행했다.
실행은 완료했지만 **변경안의 검증 성능은 낮아져 기본안으로 승격하지 않는다.**
운영 Flow·API·published Ontology에는 연결하지 않았다.

## 표본과 정답

- 코퍼스: 기존 `dictionary_rebuild_2026_10_20/source_manifest.json`의 실제 규격서 20건.
  다른 첨부파일 전체나 합성 fixture를 20건에 섞지 않았다.
- 개발 16건·검증 4건. 동일 공고·원본 hash 연결 그룹은 분리하지 않았고,
  앞서 상세 검토한 서버 10건은 모두 개발에 배정했다.
- 문서별 수치 질문 5개·답할 수 없는 질문 1개로 총 120문항이다.
  개발 96문항, 검증 24문항이며 각각 별도 Codex 호출로 정답을 검토했다.
- 원본·파싱 결과 20건의 hash와 질문·정답·분할을 고정하고, 최종 검증 전에
  선택 프롬프트·사전·채점/정규화 코드·개발 결과도 고정했다.
- 정답은 사람 검수 전 **silver label**이다. 개발 정답 감사에서 10문항의 기준이
  모호하고 1문항의 정답이 잘못됐을 가능성을 표시했다. 원래 정답과 분모는 유지했다.

## 평가 결과

모든 최종 비교에는 `v2_evidence_containment` 기준을 사용했다.
정답 원문 구간 포함, 값·단위·부등호·설치/지원·전체/개별 범위를 검사하고,
별도 Codex 채점자가 장비 귀속과 속성 의미의 동치를 검토한다.

| 버전 | 개발 | 검증 | 판단 |
|---|---:|---:|---|
| 기존 추출 프롬프트 | 77/96 (80.2%) | 20/24 (83.3%) | 비교 기준 유지 |
| Harness2 후보 00 | 70/96 (72.9%) | 미실행 | 개발에서 탈락 |
| Harness2 후보 01 | 62/96 (64.6%) | 미실행 | 개발에서 탈락 |
| 기존 프롬프트 + 원문 대조 + 사전 매핑 | 83/96 (86.5%) | 13/24 (54.2%) | 검증 개선 실패 |

개발에서는 6문항 늘었지만 검증에서는 7문항 줄었다. 이 결과로 일반화 성능이
개선됐다고 주장하지 않는다. 검증 결과를 보고 프롬프트·사전·채점기를 다시 조정하지 않았다.

검증 변경안의 실패 태그는 인용 구간 불일치 5, aggregation 2, configuration 2,
값/단위 1, 장비 귀속 의미 1이다. 태그는 실제 의미 오류와 일대일 대응하지 않는다.
다른 유효한 원문 구간을 인용한 답도 현재 기준에서 탈락할 수 있다.
따라서 이 수치를 일반적인 검색 정확도나 속성 사전의 의미 정확도로 부르지 않는다.

## 실행한 개선과 남긴 후보

Harness2 commit `1cfe254e8d25b15f37048c3730134686abe60335`의 실제
Propose–Probe–Compose를 개발 문서 2건에서 sequential, k=1로 실행했다.
실행과 proposer 모두 Codex CLI를 사용했다. 두 문서 실행은 성공했으나 경험 기록은
모두 `NO_ENTRY`여서 지속 학습이나 다음 문서 경험 재사용을 성과로 집계하지 않는다.
프롬프트 두 후보는 개발에서 더 나빠 채택하지 않았다.

개발 오류를 근거로 다음을 실험 코드에 구현했다.

- 원문 대조 단계: 질문·정답 없이 누락된 소프트웨어·운영 수치와 범위·귀속을 검토한다.
  첫 추출 결과와 대조 결과를 각각 보존한다.
- 사전 적용: 유일한 별칭 또는 관찰 이름·단위·범위의 대응만 후보 속성 ID에 연결한다.
  정규화 시 값·부등호·범위를 유지하고, 애매하거나 새로 나온 이름을 강제로 연결하지 않는다.
- 채점기: 공백 제거로 `D7 96GB`를 `D796GB`로 합쳐 정상 값을 거부하던 문제를 수정했다.
  정답 구간을 포함하는 더 긴 원문 인용도 허용했다. 이 수정 후 기존안과 모든 후보를
  동일 기준으로 다시 채점했고, 그전에 검증셋은 채점하지 않았다.
- 실행 안정성: 추출 fact에 없는 답을 거부하고, 취소 시 Codex 프로세스 그룹과 파이프를
  정리한다. 입력·프롬프트 캐시의 변경과 고정 파일 변경도 검사한다.

원문 대조 후 개발 관찰 770개·원문 속성명 180종을 모았다. 계약·근거 검사에서
20개 관찰을 제외하고, 310개 관찰 그룹을 의미 통합·별도 검토했다.
결과는 속성 **후보 122개·보류 그룹 19개**이며 미승인이다. 수가 줄었다는 이유로
정제된 표준 사전이라고 판단하지 않는다.

검증 문서 229개 fact 중 후보 ID 매핑은 127개(55.5%), 미매핑 87개,
모호한 매핑 15개다. 매핑 수는 의미 정확도가 아니며 검증 문서의 새 표현을 사전에
추가하지 않았다. 미매핑 관찰도 원문과 함께 보존했다.

## 다음 수정의 근거

변경 전 개발 오류 감사인 `improvements.json`에는 다음을 기록했다.

1. aggregation의 기준 객체와 configuration의 적용 범위를 먼저 정의해야 한다.
   서버당 CPU 수량의 total/per_instance, CPU 고유 성능의 installed/not_applicable처럼
   같은 원문에 두 해석이 가능한 정답이 존재한다.
2. 최대 정격 속성값과 요구 범위의 상한을 구별해야 한다.
3. 소프트웨어·운영 요구를 하드웨어 속성과 구분하면서도 수치 관찰에서 누락하지 않아야 한다.
4. 표의 장비 행·모델·부품·수량 문맥을 유지하고, 단순 인용 일치와 의미적 뒷받침을 구분해야 한다.

이 목록은 개발 자료에서 찾은 수정 근거다. 검증 성능 하락의 원인을 위 항목으로
확정하지 않는다. 다음 버전에서는 의미 계약과 정답 검토를 선행하고 새 검증 표본이 필요하다.

## 검증과 재현

- Pipeline 테스트: 274 passed, 19 skipped. 기존 Prefect Mermaid 경고 1건.
- 원본·native hash 20건, 공고·원본의 분할 중복 방지, 고정 코드·사전 checksum,
  310개 그룹의 누락·중복 없는 매핑을 확인했다.
- 같은 `run` 명령을 재실행해 모델 호출 캐시와 고정 결과를 재사용했고 같은 점수를 얻었다.
- 수치 QA만 평가했다. 전체 속성 회수율, 관계 정확도, 공고 목록 검색의 정밀도·회수율은 미측정이다.
- 기존 코퍼스의 사후 분리이며 같은 Codex backend가 정답 생성·검토·답안·의미 채점에 참여했다.
  미지 문서의 독립 정확도나 사람 정답 기반 평가가 아니다. 유사 템플릿 누출은 별도 감사 전이다.
