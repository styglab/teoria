# 초기 사전 구축 파이프라인 구현 검증

현재 구성·근거·적합성 모듈을 재사용하고, 관찰·사전 초안·최종 검토·실행 조립을
별도 모듈로 구현했다. 삭제한 예전 구축 모듈을 복원하지 않았다.

## 검증 범위

합성 공고 10건씩 두 배치를 사용한 계약 검증이다. 실제 공고·실제 파싱·실제 LLM
추출의 정확도 시험이 아니다. 입력·제안·최종 검토를 테스트 fixture로 작성했다.
따라서 **실제 신규 공고 처리 0건, 실제 사전 구축·승인 0건**이다.

각 합성 배치에는 실제 장착 메모리, 최대 지원 메모리, CPU 기본 클럭, CPU 부스트
클럭 관찰을 넣었다. 첫 배치 관찰 40개를 서로 다른 의미의 정의 4개에 연결했다.
다음 배치도 기존 정의를 재사용하며 같은 속성을 다시 생성하지 않았다.

## 실제 CLI로 실행한 수정·재검증

1. `prepare`: 합성 10건 입력을 검증하고 스냅샷·문서별 분석 입력 생성.
2. `collect`: 관찰·구성·원문 범위를 검사하고 사전 의미 통합 입력 생성.
3. `build r1`: 최대 지원량을 장착량 속성에 잘못 연결한 제안을 넣어 차단 확인.
4. `check r1`: 원문 대조 문제를 기록하고 승인 불가 확인.
5. `build r2`: 매핑 수정, 이전 초안 해시·검토·변경 사유 연결.
6. `check r2 + 이전 검토`: 오래된 검토 결과 재사용 거부 확인.
7. `check r2 + 새 검토`: 이전 문제의 해결 기록과 전체 항목 확인 후 통과.
8. `approve`: 합성 테스트 전용 로컬 승인 파일 생성. 게시·운영 변경 없음.
9. 다음 합성 10건에서 승인 파일을 기준으로 정의 4개 재사용 확인.

별도 단위 테스트에서는 다음 배치의 원문 동의어를 기존 정의에 추가하고,
이전 승인 파일의 해시가 변경되지 않는지도 확인한다.

## 차단·한계 확인

| 시험 | 기대 동작 |
|---|---|
| 입력 5건 또는 같은 공고·원본 중복 | 배치 준비 거부 |
| OCR 사용·기록 누락·입력 해시 변경 | 입력 거부 |
| 원문에 없는 값·조건, 숫자 일부만 일치 | 관찰 검사 차단 |
| 잘못된 대상·장착/지원·단위 차원 | 초안 문제 기록 |
| AND/OR/IF 참조 오류·순환 | 관찰 검사 차단 |
| 텍스트 범위 누락·미확인 이미지 보류 | 승인 차단 |
| 원문 없는 동의어·근거 없는 신규 속성 | 초안 문제 기록 |
| 검토 누락·미해결 문제·이전 지적사항 삭제 | 승인 차단 |
| 초안·관찰·정의·원본 스냅샷 변경 | 재계산 실패 또는 새 검토 요구 |
| 이미 승인 배치에 사용한 공고 재투입 | 다음 배치 거부 |
| 자유 의미 후보의 이름만 다름 | 문자열 ID 일치를 강제하지 않고 의미 검토 항목 유지 |

이 검사는 올바른 의미 판단의 충분조건이 아니다. 예를 들어 사람이 틀린 대상 범위와
의미 후보를 일관되게 작성하고 최종 검토까지 잘못 통과시키면 코드가 모두 판별할 수
없다. 관찰·정의·유형·범위·논리·의미 중복을 원문과 대조하는 최종 검토를 유지한다.

## 파일 위치

저장소 루트의 `.artifacts/procurement_specifications/dictionary_bootstrap_implementation_2026_10_20/`:

| 파일 | 내용 |
|---|---|
| `verification.json` | 합성 CLI 시나리오·단계별 종료 코드 |
| `r1/draft.json`, `r1_check.json` | 잘못된 매핑과 차단 사유 |
| `r2/attributes.csv` | 수정한 합성 속성 정의 4개 |
| `r2/requirements.json` | 합성 원문 관찰 40개와 연결 |
| `r2_review.json`, `r2_check.json` | 새 검토와 최종 통과 |
| `stale_review_check.json` | 이전 검토 재사용 거부 |
| `synthetic_approved_dictionary.json` | 테스트 전용 로컬 승인 파일 |
| `next_draft/draft.json` | 두 번째 합성 배치에서 기존 정의 재사용 |

실제 문서에 사용할 절차와 현재 지원 범위는 [초기 사전 구축](../dictionary_building_pipeline.md)을 따른다.

## 실행 검사 결과

새 구축 경로 테스트 36개를 포함해 Pipeline 전체 **261개 통과·16개 건너뜀**이었다.
기존 Prefect 그래프 경고 1개가 있었으며 전체 실행 시간은 52.71초였다.
문서 79개·로컬 링크 447개 검사와 변경 내용의 공백 검사에서 오류가 없었다.
저장한 r1 실패·이전 검토 재사용 거부·r2 통과 결과도 현재 모듈로 다시 계산해 확인했다.
