# 목차·표 추출 검증 — 2026-10-22

현재 보관된 `kory-parser` 0.8.0을 원문 13건에 다시 실행했다.
**선택한 표의 격자·셀·병합 복원은 양호하지만, 목차 계층과 본문 연결은 부족하다.**
공고의 품목·속성 구조화에 바로 사용할 수 있는 완성된 문서 계층이라고 보기는 어렵다.
파서 구현과 활성 프로젝트의 의존성·배포는 수정하지 않았다.

## 범위와 근거

- 기존 규격서 10건: PDF 5건, HWP 2건, HWPX 2건, DOCX 1건.
- 목차 검증: 한국어 e-ICU 규격서 PDF 1건, GNU Make 매뉴얼 PDF와 RFC 9110 PDF.
  매뉴얼과 RFC는 기존에 보관한 앞 24쪽을 사용했다.
- 목차는 원본 PDF 렌더링을 보고 선정한 14개 항목을 검사했다. PDF 목차 전체 정확도가
  아니며 HWP/HWPX/DOCX의 실제 목차 품질은 이번에 검증하지 않았다.
- HWP 셀은 원본 OLE 레코드, HWPX/DOCX 셀은 원본 ZIP/XML을 별도 검증 코드로 읽었다.
  PDF 표는 기존 원문 대조 항목과 이번에 렌더링을 확인한 e-ICU 수량 표를 사용했다.
  과거 파서 출력이나 원본 kordoc 출력을 정답으로 사용하지 않았다.
- 원문 SHA-256을 기존 manifest와 대조한 뒤 새로 파싱했다. OCR과 이미지 바이트 추출은 껐다.
  기존에 사용했던 표본을 이용한 진단이며 독립적인 신규 표본 평가는 아니다.

실행 자체는 12/13건 성공했다. 글자층 없는 `doc_09`는 OCR을 끈 조건에서
`NEEDS_OCR`로 실패했다. `success`는 구조 품질 통과나 규격 누락 없음의 의미가 아니다.
검사 종류의 분모가 다르므로 이 수치를 합쳐 전체 정확도로 표현하지 않는다.

## 확인된 한계

1. **목차 구조 계약이 없다.** `Block`에는 전용 목차 항목, 부모 항목 ID, 참조 쪽 번호,
   본문 목적지 연결이 없다. 일반 paragraph/heading/list로 표현되므로
   항목 글자가 남아 있어도 바로 탐색 가능한 목차 트리가 되지는 않는다.
2. **GNU Make 하위 항목이 합쳐진다.** 물리 7쪽에서 `1.1`과 `1.2`가 한 paragraph이고,
   `2.1`~`2.7`도 한 paragraph다. 상위 장은 heading level 1로 남지만 하위 계층은 없다.
   합쳐진 블록에 물리 줄 좌표 `regions`가 남아 있어 일부 복구 근거는 존재한다.
3. **RFC 하위 계층이 없다.** 물리 2쪽의 `1. Introduction`은 list level 1이지만
   `1.1. Purpose`는 level 없는 paragraph다. 번호 텍스트에서 사람이 계층을 읽을 수 있는
   것과 추출 계약이 계층을 제공하는 것은 구분했다. 원본 목차에는 참조 쪽 번호가 없다.
4. **한국어 장 제목이 잘못 분리된다.** e-ICU 문서의 목차 3개 항목과 참조 쪽 번호
   3·5·8은 보존됐다. 본문에서는 `Ⅰ`가 heading level 3, `일반사항`이 level 4로
   분리된다. `Ⅱ 특수조건`, `Ⅲ 물품규격`도 같다. 명시적인 목차→본문 연결은 없다.
5. **표 헤더와 데이터의 역할은 별도 검증이 필요하다.** `has_header`는 공통 생성기에서
   `rows > 1`로 설정된다. HWP/HWPX는 원본 header flag를 읽지만 PDF/DOCX는 셀 헤더 역할을
   추론하지 않는다. e-ICU 8쪽의 6×2 표는 병원별 수량 8·2·2·2와 합계 14를 모두 정확하게
   담지만, 상단 `서버` 셀도 `is_header=false`다. false를 헤더가 아니라는 확정으로 쓰면 안 된다.
6. **원문 위치와 의미 연결은 다르다.** 파싱된 표 anchor 셀에는 `SourceRef`가 있지만
   이것만으로 상위 장 제목·품목·공통조건과의 의미 관계가 생성되지는 않는다.
   HWP/HWPX의 section 근사를 물리 쪽 번호로 취급해서도 안 된다.
7. **이미지 표·혼합 PDF는 이번 통과 범위가 아니다.** `doc_10`은 실행 성공이어도
   `UNEXTRACTED_IMAGE_TEXT`가 215개 남았다. 표 검사 결과로 이미지 안 규격의 복원이나
   OCR 표 구조 품질을 주장하지 않는다.

구조화 화면을 만들 때 표 격자·병합·셀 근거는 활용 가능하다. 목차 항목 분리와 계층,
장 번호·제목 결합, 헤더 역할과 제목→표 연결은 보완·검토 대상으로 남겨야 한다.

## 재현

기존 원문과 manifest가 있는 환경에서 새 출력 디렉터리를 지정한다.
원문이 포함된 native JSON은 `.artifacts/`에만 저장한다.

```bash
archive/kory_parser/.venv/bin/python \
  archive/kory_parser/verification/toc_table_review.py \
  --output archive/kory_parser/.artifacts/toc_table_review_repeat
```
