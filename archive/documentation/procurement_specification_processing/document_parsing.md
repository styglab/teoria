# 문서 파싱 모듈 설계

현재 서버 표준 관리 실험은 [Kory Parser 0.9.4 기반 실행](pipeline_2026_10_27.md#서버-표준-관리-1차-실행)을 따른다. 아래 kordoc 권장안은 이전 비교·설계 기록이며 현재 실험의 실행 파서를 뜻하지 않는다.

현재 권장안은 **kordoc 구조 파싱 + 형식별 원본 검사·근거 연결**이다.
[OCR 제외 비교 결과](parser_evaluation_2026_10_20.md)를 바탕으로 책임·입출력·보존
기준을 정리한다. 아래는 구현 기준과 공통 Document JSON의 최소 계약 초안이다.
운영 모듈·최종 JSON Schema·DB migration·Flow 연결은 아직 구현하지 않았다.

## 범위와 독립 실행

`document_parsing`은 확보된 **원본 파일과 명시적인 파서 설정**을 입력받아 문서
내용·구조·위치·진단을 반환한다. 첨부 선별·다운로드·문서 qualification·품목 식별·
요구조건 추출을 내부에서 자동 실행하지 않는다. 파일명으로 실제 형식을 확정하지
않으며 원본 signature·패키지 구조·암호화·손상을 검사한다.

같은 원본을 다른 파서·설정으로 실행할 수 있다. 기존 native 출력과 정규화 결과를
별도로 보존하고, 특정 결과를 후속 입력으로 명시적으로 선택한다. 새 실행이 기존
승인 결과를 자동 교체하지 않는다. 상위 실행의 다운로드·저장·재시도는 실행 진입점과
Prefect Flow의 책임이다. [독립 실행 원칙](overview.md#모듈별-독립-실행-구현-원칙)을 따른다.

## 처리 흐름

1. 원본 참조·hash·설정·실제 형식과 처리 예산을 검사한다.
2. OCR을 명시적으로 끄고 선택한 parser adapter를 실행한다.
3. native 출력·진단·도구 버전·설정·실행 정보를 보존한다.
4. 원본 형식의 구조·변경 추적과 확보 가능한 근거를 대조한다.
5. 공통 JSON으로 변환하면서 native 참조·원본 anchor·정보 부재 사유를 유지한다.
6. 파싱 품질 검사 결과와 검수 범위를 반환한다. 실제 발주 요구규격 여부는 판단하지 않는다.

파싱은 동기 CPU 작업으로 격리하고, 상위 비동기 경로가 제한된 Job·Task 실행을
사용한다. HTTP·DB는 소유 프로젝트의 native async 경계로 처리한다.

## 도구 선택과 adapter 경계

| 대안 | 장점 | 한계 | 현재 판단 |
|---|---|---|---|
| kordoc 단독 기본 출력 | 형식별 구조를 같은 API에서 얻고 중첩·병합 표 보존 사례 확인 | 성공·품질 플래그만으로 미추출을 알 수 없음 | 원본 검사 없이 채택하지 않음 |
| 문서마다 모든 도구 실행 | 차이·실패 발견에 유리 | 비용·운영 복잡도, 불일치의 정답은 여전히 필요 | 평가 표본에 사용 |
| kordoc 기본 + 형식별 검사 + 필요한 경우 대체 파서 | 구조 출력과 원본 근거를 함께 관리 | 검사·근거 adapter의 구현·검증 필요 | 현재 권장 |

Adapter는 명시된 원본·설정으로 native 결과를 만드는 경계다. 도구별 출력을 먼저
보존하고 공통 JSON 정규화는 별도 책임으로 둔다. native 보존 오류와 정규화 시
생긴 오류를 구분하기 위해 두 결과를 함께 검사한다. 모든 후보 adapter를 미리
구현하거나 자동 fallback을 무제한 반복하지 않는다.

| 형식 | 원본 검사의 핵심 |
|---|---|
| PDF | native text 유무, 이미지·도형·페이지 크기, 좌표계·읽기 순서·표의 원문 대응 |
| HWP | BodyText/Section 원본 레코드와 추출 문구 연결, 표·셀 정보 교차 확인 |
| HWPX | ZIP part·XML anchor·표 원본 ID·셀 주소·병합·삭제/삽입 표식 |
| DOCX | 원본 XML의 표·행·셀·문단 순서와 span·변경 추적, 문단·run 속성 |
| XLSX | 후보 지원 범위 확인 후 별도 평가. 현재 실제 표본 검증 없음 |

기본 파서의 불일치를 다른 도구가 반환한 값으로 조용히 덮어쓰지 않는다. 대체 결과도
같은 원문 기준으로 검증하고 선택 이유·설정·원래 결과를 남긴다.

## 보존 설정

현재 비교한 기준 버전은 kordoc 4.22.15다. `ocr: false`, `formulaOcr: false`,
`images: false`, `removeHeaderFooter: false`, `dedupeRunningHeaders: false`를
명시한다. HWP/HWPX에는 `layoutTables: "keep"`, `keepTrailingEmptyCols: true`,
`keepEmptyParagraphs: true`를 적용한다. 이 옵션을 PDF에 일괄 적용하지 않는다.
옵션의 실제 지원 범위와 부작용은 도구 버전·형식별 테스트로 관리한다.

`images: false`는 이미지 바이트를 native 결과에 중복 탑재하지 않는 설정이다.
이미지 자리·원본 참조·미추출 상태까지 없애도 된다는 뜻은 아니다. 그림·비텍스트
영역의 요구규격은 이번 범위에서 복원하지 않는다. 수식 OCR도 별도로 비활성화한다.

## 공통 Document JSON 최소 계약

파서별 정보 보존 범위가 다르므로 모든 위치·제목 수준을 필수값으로 강제하지 않는다.
필드가 없을 때 부재 사유와 native 보존 정보를 함께 제공한다. 최종 JSON Schema는
이 계약을 실제 adapter 출력으로 확인한 뒤 확정한다.

| 영역 | 최소 정보와 의미 |
|---|---|
| 원본 | 원본 artifact 참조·SHA-256·실제 형식·bytes·원본 파일명 |
| 실행 | parse run ID·parser 버전·명시적 옵션·정규화 계약 버전·실행 시간·기술적 실행 상태 |
| native 결과 | 출력·로그 참조와 checksum. Markdown만 저장하지 않음 |
| 문서 요소 | run 내 고유 ID·종류·원문 텍스트·순서·부모/자식·native 요소 참조 |
| 표 | 원본 표 ID가 있으면 보존, 행·열 수·셀 시작 주소·row/column span·중첩 관계 |
| 제목 계층 | native heading/outline·style·번호·부모 section. 추론 여부와 근거, 미확정 허용 |
| 근거 | 원본 part/stream·XML/레코드 anchor, 페이지·좌표·좌표계와 근거 방식 |
| 변경 추적 | 현재 본문 정책·삭제/삽입 표식 참조·해석 불가 상태. 원본은 변경 이력을 포함해 보존 |
| 미추출 영역 | 이미지·비텍스트·부분 실패 영역·위치·원본 참조·미추출 사유 |
| 품질 결과 | 검사 항목·범위·실패/보류·심각도·검수 상태·정보 부재 사유 |

문서 요소 ID는 `parse_run` 범위에서 유일하다. 다른 파싱 실행의 배열 번호나
내부 글꼴 토큰을 Stable Source ID로 사용하지 않는다. XML anchor는 ZIP part와
원본 checksum에 연결하고, 동일 ID가 반복되는 문서는 XML 경로·순번으로 구분한다.

페이지 근거는 native PDF 페이지, 저장된 조판 정보, section 근사치를 구분한다.
PDF bbox는 단위·원점·페이지 크기를 함께 보존하고 변환 전 좌표도 남긴다.
HWPX의 원본 table ID는 source ID이며 새로 부여한 문서 요소 ID와 구분한다.

파서의 `hasHeader` 등 휴리스틱 결과는 확정된 의미 관계로 승격하지 않는다.
현재 본문 텍스트와 서식용 Markdown·정규화 텍스트를 구분하고, 숫자·단위·기호를
정규화하면서 원문 값을 덮어쓰지 않는다. 속성 의미·품목 귀속·`contains_requirements`는
이 계약에서 파서가 확정할 필드가 아니다.

## 품질 검사와 후속 전달

| 확인 사례 | 처리 기준 |
|---|---|
| 파서는 success이나 본문이 비어 있음 | 원본 화면·도형·영역에 근거해 미추출 검사, 자동 분석 보류 |
| 이미지가 포함된 규격 구간 | 영역과 근거를 보존하고 해당 조건은 미확인. `needsOcr=false`로 통과시키지 않음 |
| 원본과 출력의 표 개수가 다름 | 먼저 삭제·삽입·중첩·레이아웃 여부를 확인. 개수만으로 누락 단정 금지 |
| 표·셀·수량 관계가 다름 | 변경 이력과 현재 본문을 대조해 오류/보류를 기록 |
| 제목 계층이 native에 없음 | 원문 번호·서식·순서를 보존. 추론한 계층은 검토 전 확정하지 않음 |
| 원문 anchor 연결 불가 | 그 구간의 자동 분석 보류 |
| 같은 원본의 다른 파서 결과가 충돌 | 양쪽 결과·근거를 보존하고 검토. 다수결·모델 보정으로 확정하지 않음 |

파서의 기술적 실행 상태와 품질 판정을 분리한다. 품질 판정에도 전체 문서/검증된
구간/미확인 영역을 명시한다. 구간만 확인했다면 문서 전체가 정상이라는 결과를
반환하지 않는다. qualification에는 파싱된 문서 구조와 이 범위·진단을 함께 전달한다.

동일 실행의 retry는 중복 저장을 방지하고, 설정·도구·정답 기준 변경은 새 run으로
보존한다. OCR은 현재 fallback 대상이 아니다. 암호화·손상·미지원 입력은 원인에
따라 보류하며 같은 실패를 무제한 재시도하지 않는다.

## 다음 구현과 검증 순서

1. 검증된 원본·파서 설정과 native 결과 보존을 독립 실행 경계로 구현한다.
2. 원본 anchor·변경 추적·좌표 변환을 실제 결과에 연결한다.
3. 공통 JSON 정규화 후 원문 셀·숫자·단위·범위·근거의 보존을 재평가한다.
4. HWP 시각 구조·활성 병합 HWPX·연속 표·추가 DOCX·XLSX를 확대 검증한다.
5. 통과 범위와 보류 계약을 확정하고 의미 분석 배치에 전달한다. 이전 문서 적합성 모듈은 삭제했다.

원문 기준과 성공·보류는 [평가 기준서](parser_evaluation_criteria.md)를 따르며,
현재 비교에서 확인한 범위를 넘어 지원·정확성을 주장하지 않는다.
