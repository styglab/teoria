# 구현 상태와 다음 작업

Teoria는 AI-Native Metadata & Ontology Platform이다. FormatID(규격서 기반 물품 구조화·분석)는 첫 업무 앱이며,
메타데이터 정비·Ontology·의미 연결·Runtime 기반과 구분해 발전시킨다.

Compose는 공통 기반과 `mlops`·`semantic`·`formatid`를 조합하고 선택된 기능의 API·메뉴·Workflow를 활성화한다.
MLflow는 Platform PostgreSQL의 전용 DB·계정을 공유한다.
초기화 작업은 일회성 컨테이너로 실행·정리하며 배포·중지 명령은 [운영 안내](deployment/compose.md)를 따른다.
이 변경의 설정·테스트 검증과 실제 Docker 서비스 기동 검증은 구분한다. K3s의 선택형 모듈 배포는 아직 제공하지 않는다.
로컬의 모듈별 단독 실행·전체 재시작과 대표 Flow 실행은 [Compose 검증 기록](verification/compose_modules_2026_10_30.md)에 남겼다.

## 다음 순서

물품 공고의 원문 버전·관측·첨부 참조를 [운영 DB에 복원](../archive/documentation/verification/goods_notice_production_restore_2026_10_28.md)했다.
보관 공고의 분류·기간으로 규격서 후보를 선정·확보하는 명시적 실행 경로를 제공한다.
물품 공고의 증분 수집 계약·Flow 검증, 선정·확보 품질과 독립 평가는 후속이다. 구형 조달 전체 수집은 재개하지 않는다.

| 순서 | 작업 | 확인할 결과 |
|---|---|---|
| 1 | 같은 대상의 표현·별칭 정렬 | 원문 이름을 보존하면서 근거 있는 동일 대상만 연결 |
| 2 | 보류 관계·공통 조건의 귀속 정리 | 속성 판정에서 원문에 명시된 구성 누락 검토, 기본 물품 구성과 기존 장비·설치 지원 분리; 품목별 관계 품질 검증 지속 |
| 3 | 표준 사전·매핑 확대 | 물품 유형·특성 정의·적용 범위·단위 정책과 판정 근거 확보 |
| 4 | goods 모델의 게시·프로파일·데이터 연결 | 승인 의미와 문서별 관찰을 구분한 조회 경로 확보 |
| 5 | 구조 탐색·유사 물품 검색·비교 | 구성·속성·조건과 근거를 함께 조회하고 활용별 질문으로 검증 |
| 6 | 독립 품질 평가와 변경 영향 확인 | 알려진 문서의 회귀와 독립 표본 평가를 구분하고 영향 문서·재처리 범위 확인 |

추출 상태는 핵심 구성·속성 문제와 부가 관계 검토를 구분한다. 통신·호환·의존·지원·작업·문서 관계의 보류는
보존하되 단독으로 추출 실패·부분 완료를 만들지 않는다. 종류 미확정·동일 대상·구성 관계와 속성 오류는 계속 확인한다.
명시적 구성 목록의 경계·순서를 추출 결과에 보존하고 상세 대상의 최상위 이동을 검증한다.
화면은 해석된 구성의 부모 연결을 검토 중으로 보존하며, 보류된 가지를 새로운 최상위 물품으로 표시하지 않는다.
Kory OCR 의존성·모델 준비, OCR 페이지·좌표 근거 보존, 독립 구매 행 귀속 검사와 제한된 누락 대상 복구를 구현했다.
고정 설치한 파서로 기존 원본 10개를 실제 추출하고 Compose Worker에 운영 배포했다.
FormatID 미분류 목록과 모든 상세 결과를 확인했으며 추출 완료 2개·부분 완료 8개·실패 0개다.
참조 안내와 실제 누락을 구분하고 S3 원본 재사용을 보완했다. 사전 의미 매핑과 독립 품질 평가는 남아 있다.
평가 종료 중 공용 상태 파일이 사라져 candidate/finish 비교는 완료하지 못했으며 개선율을 확정하지 않는다.

최근 [규격서 재점검](verification/specification_processing_recheck_2026_10_30.md)은 원문·중간 결과·판정의 불일치와 남은 문제를 기록한다.
실행 완료나 테스트 통과를 전체 의미 정확도 검증으로 표시하지 않는다. 이전 고정 원본 비교는
[관계 수정 평가](../archive/documentation/verification/goods_relation_repair_2026_10_28.md)에 보존한다.

## 현재 범위에 없는 일

이전 기업·공고·계약·낙찰 분석, 조달 API 자동 수집, 구형 첨부 자동 처리와 참가자격 판단은 비활성이다.
빈 이전 DB 객체를 정리했지만 수집·실행 이력, 법령, 물품 공고 복원 기반과 승인·게시 이력은 보존했다.
과거 기능의 실행 명령은 [보관 문서](../archive/documentation/index.md)에서만 확인한다.
K3s는 배포 구성을 제공하지만 로컬 Compose 검증만으로 실제 EC2 운영 성공을 주장하지 않는다.


프런트엔드 공통 스타일 기준은 디자인 토큰·공통 버튼/입력·포커스/셀렉트 모듈로 정리한다.
FormatID의 모바일 카드/접이식 필터, 취소 가능한 조회·제한된 메모리 캐시·목록 복귀 상태,
기본 추출 결과·원문 발췌·여러 근거 대조와 별도 표준 매핑 보기·비교 제외 이유를 제공한다. 고정 샘플의 브라우저/화면 회귀 검사를
CI에 등록하며 실제 배포 검증과 CI 실행 결과를 구별해 기록한다.

규격서 추출은 순수 설명의 별도 보존, 동일 원문 구매 수량의 중복 방지, 속성별 인용 범위 검증과
원문명과 구분한 AI 해석 표시명을 지원한다. 알려진 샘플 10개를 이용한 전후 비교는 독립 품질 평가나
표준 사전 의미 매핑 완료를 뜻하지 않는다. 관측 결과와 배포 여부는 위 누적 재점검 기록을 기준으로 한다.
2026-11-01 추가 수정으로 기존 구성의 보존 검사와 원문·모델·단계 코드에 따른 중간 관찰 재사용을
반영했다. Worker/API를 배포하고 새 모델로 추출한 알려진 샘플 10개의 검토용 결과를 갱신했다.
공식 비교의 미귀속 속성 수 증가 판정은 그대로 보존한다. 동일 포장 조건의 분할 차이를 원문으로
확인했으며, 이를 독립 정확도 향상·자동 품질 승인이나 표준 의미 매핑 완료로 표시하지 않는다.

2026-11-02 개발판은 공급 목록의 구매 행·수량을 보존하면서 상세 본문의 구성관계를 별도로 유지한다.
기준 목록 판독 상태, 제한된 PDF 표 영역 OCR 및 미확정 수량 표시를 Worker·웹에 배포했다.
샘플 10개를 새 추출로 재처리했고 원문·웹 결과를 확인했다. OCR 파서는 직렬, 모델 판정은 제한된 동시 실행을 유지한다.
운영 실행 결과와 검증 범위는 누적 기록에 남긴다.
실제 모델 비교 사이클은 실행기 오류로 중단됐으므로 자동 품질 승인이나 전후 개선으로 기록하지 않는다.
