# 문서 파서 평가 기준서

버전: **1.1**. 평가 범위는 **OCR을 사용하지 않는 문서 파싱**이며 최초 대상은
컴퓨터서버 규격서 및 유사 규격 문서다. 기존 실험에서 확보한 후보를
출발점으로 사용한다. 후보 선정은 문서의 실제 규격 포함 여부나 파싱 품질의 정답이 아니다.

## 1 목적과 평가 순서

원문의 내용과 구조가 후속 자동 분석에 필요한 수준으로 보존되는지 검증한다.
추출된 텍스트의 양만으로 성능을 판단하지 않는다.

1. 평가 기준과 표본을 확정한다.
2. 원문을 확인하여 비교 기준과 중요 평가 구간을 작성한다.
3. 후보 도구의 실제 지원 형식과 OCR 비활성화를 확인한다.
4. 동일 표본으로 실행하고 구간별 결과를 판정한다.
5. 입력 형식·문서 유형·용도별 통과 여부를 결정한다.
6. 결과를 바탕으로 공통 Document JSON을 확정한다.

## 2 평가 조건

- 모든 후보에서 OCR을 끈다. 비활성화를 확인할 수 없으면 정식 비교에서 제외하고 사유를 기록한다.
- 동일 원본을 사용하고 파일명·실제 형식·SHA-256·크기를 기록한다.
- 도구 버전·실행 옵션·환경·출력 형식을 기록한다. 기존 운영 의존성과 분리한 실험 환경을 사용한다.
- 기본 출력과 후처리 결과를 구분하고 원본 출력·후처리 규칙·버전을 보관한다.
- 미지원·실행 실패·출력 생성 실패와 정상 추출 결과를 구분한다.
- 암호화·손상 등 입력 문제와 도구 오류를 구분한다.
- 이미지 속 문자를 못 읽는 것은 예상되는 제한이다. 이미지·미추출 영역을 조용히 생략하는지는 별도로 평가한다.

문서를 외부 형식으로 변환한 경우 변환기와 파서의 조합을 평가한다. 변환에서 생긴
손실도 최종 오류에 포함한다. 외부 서비스에 문서를 전송하지 않고 로컬 도구부터 비교한다.

## 3 보존 대상과 확인 방법

| 항목 | 확인 대상 | 대표 오류 |
|---|---|---|
| 텍스트 | 문자·숫자·단위·비교기호·범위·부정 표현 | 16GB를 16MB로 변경, 이상 누락 |
| 표 구조 | 행·열·셀·병합 관계와 소속 | 한 셀을 여러 행으로 분리, 병합 범위 손실 |
| 헤더 연결 | 항목·열·품목과 조건의 관계 | 16GB가 어느 항목의 조건인지 불명확 |
| 문서 계층 | 제목·하위 제목·소속 문단과 표 | 서버 표가 스토리지 제목 아래 배치 |
| 읽기 순서 | 문단·표·셀의 논리적 순서 | 다단 문서 혼합, 셀 순서 뒤바뀜 |
| 원문 추적 | 원본 문단·표·셀을 특정할 수 있는가 | 출력 번호만 존재, 원본 대응 불가 |
| 누락 감지 | 이미지·미추출 영역·부분 실패의 표시 | 표·이미지를 경고 없이 생략 |

공백·줄바꿈 차이는 의미·구조에 영향이 없으면 허용한다. 숫자·단위·비교기호의
의미 변경은 허용하지 않는다. 추정한 헤더·제목 관계는 원천에서 직접 얻은 관계와 구분한다.

### 원문 추적 인정 조건

페이지·좌표가 제공되면 그 위치에서 원본 요소를 확인할 수 있어야 한다. 해당 위치를
제공하지 않는 형식은 문단·표·셀 식별자, 원본과의 대응 관계, 동일 원본·설정에서의
대응 재현성을 모두 확인한다. 출력에만 임의 번호가 있으면 추적 가능으로 인정하지 않는다.
재실행의 출력 ID가 달라도 원본 anchor와의 대응이 재현되는지는 별도로 확인한다.

## 4 비교 표본과 원문 정답

| 표본 유형 | 중점 확인 |
|---|---|
| 단순 표 | 행·열·셀 및 항목–조건 연결 |
| 병합 셀이 많은 표 | 병합 범위와 상위 헤더 적용 |
| 다품목 문서 | 품목 경계와 조건 소속 |
| 여러 페이지의 표 | 연속성·반복 헤더·페이지 경계 |
| 텍스트·이미지 혼합 | 읽기 순서·이미지·미추출 영역 |

평가 구간과 기대 텍스트·수치·단위·기호·표 관계·제목·순서·이미지 존재를 후보 실행
전에 원문에서 기록한다. 기록 작성자·검토자·작성일·원문 식별 방법과 확인 범위를 남긴다.
원문 XML·바이너리 레코드 조사와 원본 화면의 시각 대조를 구분하고, 시각 대조하지 않은
구조를 시각 검수 완료로 표시하지 않는다. 후보 출력 자체를 원문 정답으로 삼지 않는다.

원문 자체가 모호한 관계는 모호성을 보존하고 해당 의미 관계의 정답 판정에서 제외한다.
기준을 수정하면 사유·버전을 기록하고 모든 도구에 같은 수정 기준을 재적용한다.

### 변경 추적과 현재 본문

현재 발주 요구규격 분석의 기준은 **삭제된 변경 내용은 제외하고 삽입된 내용은 포함한
현재 본문**이다. 원본 파일·변경 표식·삭제된 내용은 감사 근거로 별도 보존한다.
변경 추적 중인 표·셀·문장을 구분하지 않고 원본 XML 개수나 모든 텍스트를 단순 합산해
정답으로 사용하지 않는다. 표식의 범위·상태를 해석하지 못하면 해당 구간을 보류한다.
링크 제어 명령·필드 내부 설정 문자열도 표시되는 본문과 구분한다.

1.1에서는 실제 HWPX의 삭제 표를 누락으로 오판하지 않도록 이 기준을 추가했다.
첫 원문 기준과 수정 기준·사유·hash를 보관하고 모든 후보에 같은 현재 본문 기준을
재적용한다. 수정은 파서의 오류를 없애기 위한 임의 정답 변경이 아니라 원본의
`deleteBegin`·`deleteEnd`와 삽입 표식에 근거한다.

## 5 판정 체계

판정 단위는 **평가 구간 × 평가 항목**이다. 판정과 심각도를 별도로 기록한다.

| 판정 | 정의 |
|---|---|
| 보존 | 대상 정보·관계가 정확하게 유지됨 |
| 일부 손실 | 일부 손상되었으나 나머지는 확인 가능 |
| 손실 | 누락·변경되었거나 신뢰할 수 없음 |
| 해당 없음 | 원문 구간에 해당 항목이 없음 |

평가 근거가 부족하면 판정을 보류하고 사유를 기록한다. 보류를 보존이나 해당 없음으로
대체하지 않는다. 실행 실패·미지원도 해당 없음으로 세지 않는다. `메모리 | DDR5 16GB 이상`의
문자만 남고 항목과 조건이 분리되면 텍스트는 보존, 표·헤더 관계는 손실이며 관계를
복원할 근거가 없으면 중대 오류다.

평가자가 수동으로 발견한 오류와 운영에서 자동 탐지 가능한 오류를 구분한다.
실험에서 오류를 발견했다는 사실만으로 운영 시스템이 자동 감지한다고 가정하지 않는다.

## 6 중대 오류와 통과 기준

| 중대 오류 | 적용 기준 |
|---|---|
| 숫자·단위·연산자 변경·누락 | 조건 의미가 달라지거나 확정 불가 |
| 다른 품목과 조건 혼입 | 조건 소속이 잘못 연결됨 |
| 근거 추적 불가 | 분석 내용의 원본 위치 확인 불가 |
| 필수 규격·소속 관계 손실 | 필요한 조건 누락 또는 수식 대상 불명 |
| 중요 영역의 조용한 누락 | 표·이미지·영역이 표시 없이 사라짐 |

자동 분석에 통과시키려면 정상 파싱, 중대 오류 없음, 필요한 모든 항목 보존,
분석에 영향을 주는 미확인 영역 없음의 네 조건을 모두 충족해야 한다.
중대 오류가 하나라도 있으면 평균 점수와 무관하게 해당 결과를 통과시키지 않는다.

구간 한정 통과와 전체 문서 통과를 구분한다. 구간 검사만으로 문서 전체 통과를
주장하지 않는다. 검증된 구간만 사용할 경우 분석 범위·제외 영역을 명시한다.
수정한 결과는 수정 전 출력·후처리 규칙을 남기고 다시 평가한다. 적합성은 검증한
입력 형식·문서 유형·설정에 한정하며 전체 문서 모집단의 정확성을 보장하지 않는다.

## 7 실행 및 성능 기록

입력을 도구에 전달한 시점부터 출력이 준비될 때까지 시간을 측정한다. 설치·모델
다운로드·최초 초기화 시간은 별도로 기록한다. 속도 순위는 동일 조건에서 반복한
중앙값으로만 비교한다. 초기 1회 실행은 진단 시간이며 성능 순위가 아니다.

| 기록 항목 | 내용 |
|---|---|
| 실행 식별자 | 문서·도구·설정·반복 차수 |
| 도구 | 제품·정확한 버전·공식 근거 확인일 |
| 입력 | 원본 참조·형식·hash·bytes·확인 가능한 페이지 수 |
| 설정 | OCR 끔·옵션·후처리·모델 버전 |
| 환경 | 로컬/원격·OS·CPU·메모리·실행 제한 |
| 실행 상태 | 성공·부분 성공·실패·미지원·환경 준비 실패 |
| 시간 | 처리 초·초기화·다운로드와 구분 |
| 실패·보관 | 오류·부분 출력·원본 출력·로그·설정의 위치 |

도구가 반환한 성공과 품질 평가 통과는 별개다. 환경 준비 실패를 파서 정확성 실패로
해석하지 않으며, 같은 조건으로 실행하지 못한 결과를 속도 순위에 넣지 않는다.

## 9 후보 지원 형식 확인

후보마다 공식 근거와 고정된 설치 버전의 실제 실행을 모두 확인한다.

| 후보 | 형식·제약 | 공식 근거·확인일 | OCR 비활성화 | 출력 | 실행 결과 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

확인한 공식 문서와 설치 버전의 기능이 다를 수 있으므로 버전 차이를 기록한다.
라이브러리를 설치했다는 사실만으로 실제 입력 지원을 확정하지 않는다.

## 10 공통 Document JSON 확정

원본 출력은 먼저 보존하고, 후보를 공통 schema에 강제로 맞추기 전에 기본 출력의
보존 품질을 평가한다. 이후 adapter 변환에서 추가 손실이 생기는지 따로 평가한다.

- 원본/후처리 텍스트, 문단·표·셀·병합을 구분한다.
- 제목 계층·읽기 순서·헤더 관계와 추론한 관계의 출처를 표현한다.
- 페이지·좌표 또는 원본 anchor, 이미지·미추출 영역·경고를 보존한다.
- 지원되지 않는 정보는 추정값으로 채우지 않고 부재와 사유를 기록한다.
- 품목·구성요소의 의미 확정은 후속 식별 단계의 책임으로 유지한다.

최종 schema와 파싱 모듈 구현은 평가 결과를 검토한 뒤 정한다. 전체 서비스의
모듈 경계는 [독립 실행 원칙](overview.md#모듈별-독립-실행-구현-원칙)을 따른다.
