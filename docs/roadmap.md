# 구현 상태와 다음 작업

Teoria는 AI-Native Metadata & Ontology Platform이다. FormatID(규격서 기반 물품 구조화·분석)는 첫 업무 앱이며,
메타데이터 정비·Ontology·의미 연결·Runtime 기반과 구분해 발전시킨다.

Compose는 공통 기반과 `mlops`·`semantic`·`formatid`를 조합하고 선택된 기능의 API·메뉴·Workflow를 활성화한다.
MLflow는 Platform PostgreSQL의 전용 DB·계정을 공유한다.
초기화 작업은 일회성 컨테이너로 실행·정리하며 배포·중지 명령은 [운영 안내](deployment/compose.md)를 따른다.
이 변경의 설정·테스트 검증과 실제 Docker 서비스 기동 검증은 구분한다. K3s의 선택형 모듈 배포는 아직 제공하지 않는다.
로컬의 모듈별 단독 실행·전체 재시작과 대표 Flow 실행은 [Compose 검증 기록](verification/compose_modules_2026_10_30.md)에 남겼다.

Prefect 공통 등록 정보·스케줄은 기능별 `backend/config/`, 환경별 실행 정책은
`deploy/compose/prefect/`와 `deploy/k3s/prefect/`에서 관리한다.
구현된 경로, 실제 배포 성공, 의미 품질 검증은 서로 다른 완료 기준이다.
[실제 검증 기록](verification/index.md)에서 입력·환경·결과·한계를 확인한다.


2026-10-30 [컴퓨터서버 30개 재점검](verification/specification_processing_recheck_2026_10_30.md)에서는 26개 추출 중 완전 상태 1개·부분 완료 25개였으며, 독립 평가 자료 부족과 과거 근거 파일 부재로 사전 변경은 보류됐다. 자동 사전 구축의 품질 검증은 아직 남아 있다.

## 다음 순서

물품 공고의 원문 버전·관측·첨부 참조를 [운영 DB에 복원](../archive/documentation/verification/goods_notice_production_restore_2026_10_28.md)했다.
보관 공고의 분류·기간으로 규격서 후보를 선정·확보하는 명시적 실행 경로를 제공한다.
물품 공고의 증분 수집 계약·Flow 검증, 선정·확보 품질과 독립 평가는 후속이다. 구형 조달 전체 수집은 재개하지 않는다.

| 순서 | 작업 | 확인할 결과 |
|---|---|---|
| 1 | 같은 대상의 표현·별칭 정렬 | 원문 이름을 보존하면서 근거 있는 동일 대상만 연결 |
| 2 | 보류 관계·공통 조건의 귀속 정리 | 납품 문서·작업·조건부 구성의 관계를 설명하고 잘못된 병합을 차단 |
| 3 | 표준 사전·매핑 확대 | 물품 유형·특성 정의·적용 범위·단위 정책과 판정 근거 확보 |
| 4 | goods 모델의 게시·프로파일·데이터 연결 | 승인 의미와 문서별 관찰을 구분한 조회 경로 확보 |
| 5 | 구조 탐색·유사 물품 검색·비교 | 구성·속성·조건과 근거를 함께 조회하고 활용별 질문으로 검증 |
| 6 | 독립 품질 평가와 변경 영향 확인 | 알려진 문서의 회귀와 독립 표본 평가를 구분하고 영향 문서·재처리 범위 확인 |

최근 [규격서 재점검](verification/specification_processing_recheck_2026_10_30.md)은 원문·중간 결과·판정의 불일치와 남은 문제를 기록한다.
실행 완료나 테스트 통과를 전체 의미 정확도 검증으로 표시하지 않는다. 이전 고정 원본 비교는
[관계 수정 평가](../archive/documentation/verification/goods_relation_repair_2026_10_28.md)에 보존한다.

## 현재 범위에 없는 일

이전 기업·공고·계약·낙찰 분석, 조달 API 자동 수집, 구형 첨부 자동 처리와 참가자격 판단은 비활성이다.
빈 이전 DB 객체를 정리했지만 수집·실행 이력, 법령, 물품 공고 복원 기반과 승인·게시 이력은 보존했다.
과거 기능의 실행 명령은 [보관 문서](../archive/documentation/index.md)에서만 확인한다.
K3s는 배포 구성을 제공하지만 로컬 Compose 검증만으로 실제 EC2 운영 성공을 주장하지 않는다.
