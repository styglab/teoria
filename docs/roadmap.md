# 구현 상태와 다음 작업

Teoria는 AI-Native Metadata & Ontology Platform이다. 규격서 분석은 첫 업무 앱이며,
메타데이터 정비·Ontology·의미 연결·Runtime 기반과 구분해 발전시킨다.

## 지금 가능한 일

| 영역 | 구현·사용 범위 | 남은 한계 |
|---|---|---|
| 규격서 처리 | 원본 입력부터 추출·검증·사전 연결·보고서 저장까지 실행 | 관계 의미·별칭·귀속·누락의 품질 개선 필요 |
| 규격서 화면 | 문서 입력·기존 Flow 실행·이력·구성 트리·문서 속성/표준 매핑 비교·선택 행의 원문 패널 | S3 본문 미리보기·K3s 업로드 연결은 후속 |
| 사전 | 원문 등록, Codex 의미 작성·재검증, 문서 집합의 사전 개정·영향 매핑 일괄 적용·스냅샷 고정 | 실제 모델·API로 소규모 자동 승인을 확인했으며 물품군 확대와 독립 품질 평가 필요 |
| 물품 Ontology | goods Draft와 문서 그래프 작성·검증 계약 | 새 모델의 게시·실행 데이터 연결은 후속 |
| 물품 공고 근거 | 백업의 공고 758,443건·첨부 참조 1,848,691건을 운영 DB에 복원 | 신규 자동 수집·URL 다운로드 확인·선택 문서 처리 연결은 후속 |
| 프로파일 | Published 개념을 참조하는 작성·승인·고정 패키지 적용 기반 | 현재 goods Draft용 프로파일·전체 자동 의미 작성은 미완성 |
| 메타데이터 관리 | OpenMetadata 자산 조회·진단·제안 검토·적용 | AI 제안의 근거와 권한별 검토를 계속 검증 |
| Runtime·MCP | 게시 artifact·정책·의미 연결을 사용하는 실행 기반 | 새 물품 검색·비교 Capability는 아직 없음 |
| 법령 | 전용 수집·조회와 진단 근거 연결 | 운영 범위·버전별 보존과 재처리 관리 |
| 모델 운영 | 선택형 합성 데이터 학습·평가·등록·정해진 데모 배포 | 범용 모델 승인·격리·K3s 배포 어댑터는 후속 |

구현된 경로, 실제 배포 성공, 의미 품질 검증은 서로 다른 완료 기준이다.
[실제 검증 기록](verification/index.md)에서 입력·환경·결과·한계를 확인한다.

## 다음 순서

물품 공고의 원문 버전·관측·첨부 참조를 [운영 DB에 복원](verification/goods_notice_production_restore_2026_10_28.md)했다.
후속 순서는 물품 전용 증분·과거 수집 계약/Flow 검증, 첨부 URL 확인,
명시 선택한 문서의 규격서 처리 연결이다. 구형 조달 전체 수집은 재개하지 않는다.

| 순서 | 작업 | 확인할 결과 |
|---|---|---|
| 1 | 같은 대상의 표현·별칭 정렬 | 원문 이름을 보존하면서 근거 있는 동일 대상만 연결 |
| 2 | 보류 관계·공통 조건의 귀속 정리 | 납품 문서·작업·조건부 구성의 관계를 설명하고 잘못된 병합을 차단 |
| 3 | 표준 사전·매핑 확대 | 물품 유형·특성 정의·적용 범위·단위 정책과 판정 근거 확보 |
| 4 | goods 모델의 게시·프로파일·데이터 연결 | 승인 의미와 문서별 관찰을 구분한 조회 경로 확보 |
| 5 | 구조 탐색·유사 물품 검색·비교 | 구성·속성·조건과 근거를 함께 조회하고 활용별 질문으로 검증 |
| 6 | 독립 품질 평가와 변경 영향 확인 | 알려진 문서의 회귀와 독립 표본 평가를 구분하고 영향 문서·재처리 범위 확인 |

알려진 네 규격서에서는 구성 관계·방향 검사를 수정하고 실제 Worker 반영을 확인했다.
기존 고정 사례 점수는 개선되지 않았으므로 전체 품질이 검증됐다고 표시하지 않는다.
[관계 수정 평가](verification/goods_relation_repair_2026_10_28.md)와
[운영 반영](verification/goods_relation_deployment_2026_10_28.md)은 이 차이를 기록한다.

## 현재 범위에 없는 일

이전 기업·공고·계약·낙찰 분석, 조달 API 자동 수집, 구형 첨부 자동 처리와 참가자격 판단은 비활성이다.
빈 이전 DB 객체를 정리했지만 수집·실행 이력, 법령, 물품 공고 복원 기반과 승인·게시 이력은 보존했다.
과거 기능의 실행 명령은 [보관 문서](../archive/documentation/index.md)에서만 확인한다.
K3s는 배포 구성을 제공하지만 로컬 Compose 검증만으로 실제 EC2 운영 성공을 주장하지 않는다.
