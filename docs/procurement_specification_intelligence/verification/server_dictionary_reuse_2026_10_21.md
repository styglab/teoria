# 서버 사전 고정 후 다른 문서 4건 재사용 검증

2026-10-21 서버 10건으로 만든 r2 사전을 변경하지 않고, 구축에 쓰지 않은 문서
4건에 적용했다. 운영 파이프라인 구현이 아닌 오프라인 실험이다.

## 입력과 방법

- 입력은 기존 검색 실험의 validation split 4건 전체다. 공고번호는
  R26BK01778508, R26BK01744837, R26BK01501837, R26BK01773827이다.
- 사전 구축 10건과 공고번호·원본 파일 해시가 겹치지 않는다. 다만 과거 검색 실험에서
  사용된 문서이므로 처음 접하는 문서에 대한 전향적·독립 맹검 평가라고 부르지 않는다.
- 과거 정답·분석 결과 대신 원문·파싱 결과와 고정 사전으로 현재 Codex가 관찰과
  매핑 제안을 작성했다. 전체 자동 LLM 파이프라인을 실행한 결과가 아니다.
- 사전과 입력을 먼저 해시로 고정했다. 사전 SHA256은
  `d88cdcf2333339072b4e984bf1542886c898f4f838b5f565c6acdd641a2c19f6`이다.
- 대표 속성 관찰 84건을 선택해 검증했다. 문서 전체 원자 추출·정확도·재현율 측정은 아니다.
  관찰마다 원문 근거를 보존하고 IR 검증과 기존 개념의 종류·차원·적용 대상 검사를 수행했다.

## 결과

| 대상 | 결과 |
|---|---|
| 엔티티 관찰 | 기존 개념 재사용 39건, 신규 후보 3건 |
| 속성 관찰 | 기존 정의 재사용 60건, 적용 대상 누락 보류 7건, 의미 모호 보류 2건, 신규 후보 15건 |
| 신규 속성의 서로 다른 의미 | 10종 |
| 재사용한 기존 속성 | 17종 |
| 사전 변경·승인·게시 | 없음 |

기존 사전의 핵심 약점은 의미 정의보다 좁은 적용 대상 목록이다. 예를 들어 수량에는
전원공급장치·냉각장치, 모델에는 SSD·GPU, 메모리 기술에는 GPU 메모리가 빠져 있다.
이 7건을 신규 속성으로 중복 생성하거나 제약을 무시해 매핑하지 않고 보류했다.
캐시 용량의 RAID 컨트롤러 한정도 SSD 캐시 재사용을 막았다.

새 속성 후보 10종은 저장 인터페이스, 가상 머신 수, 순차 읽기·쓰기 속도,
CUDA 코어 수, GPU 최대 소비전력, 풍량, PCIe 사용 가능 레인 수, 메모리 버스 폭,
냉각 방식이다. 새 엔티티 후보는 CPU/GPU 통합 칩, 일관성 메모리 풀, 가상 머신 그룹이다.
아직 사전에 편입하지 않았다.

종류가 명시되지 않은 CPU 클럭은 기본·최대 클럭 중 하나로 강제 매핑하지 않았다.
통합 메모리 수치도 원문의 합계와 구성 값이 맞지 않아 원문을 보존하고 보류했다.
GPU CUDA 코어와 CPU 코어, SSD 읽기 속도와 네트워크 전송률을 구분했고,
기본·부스트 클럭 및 전원공급장치의 총합·개별 용량도 분리했다.

## 산출물과 검증 한계

실험 경로는 `.artifacts/procurement_specifications/server_dictionary_reuse_2026_10_21/`다.

- `manifest.json`, `freeze.json`, `dictionary_frozen.json`: 입력과 고정 사전
- `observations/`: 문서별 엔티티·속성·관계·원문 근거
- `result/report.html`, `result/review.csv`: 사람이 볼 결과
- `result/mappings.json`, `result/document_graphs.json`: 매핑과 문서 그래프
- `result/candidate_gaps.json`: 신규·적용 대상 누락·모호성 후보
- `result/summary.json`, `result/validation.json`: 집계와 검사 결과

입력·사전 해시 불변, 구축 문서와 중복 없음, 재사용 매핑의 종류·차원·대상 검사,
잘못된 적용 대상 매핑을 거절하는 4개 부정 사례를 확인했다. 이 검사는 독립적인
의미 정답 평가가 아니다. 관찰 작성과 검토를 같은 Codex가 했으며 상태는
`needs_review`, `human_reviewed=false`다. 운영 처리 흐름은 여전히 미구현이다.

다음 개선은 신규 속성을 무조건 늘리기 전에 기존 속성의 적용 대상 정의를 검토하는
것이다. 이후 실제 새 의미만 후보로 검토·승인하고 별도 사전 버전으로 반영한다.
