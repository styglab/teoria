# 속성 사전의 구조

현재는 [구성·규격 분석](composition_analysis.md)을 검증하고 있다.
새 [초기 사전 구축](dictionary_building_pipeline.md)은 의미 후보를 통합해 초안을 만들고
최종 검토·수정·재검증 뒤 로컬 승인 파일을 생성한다.
[서버 실제 10건](verification/server_dictionary_bootstrap_2026_10_20.md)에서 속성 정의 후보
152개를 만들었지만 후속 감사에서 중복·표현 차이·문장형 요구조건이 섞인 것을 확인했다.
**152개 또는 별도 보완안 189개를 서로 다른 표준 속성 수로 간주하지 않는다.**
예전 속성 52개 초안은 입력에 사용하지 않은 과거 참고 결과다.

## 현재 초안의 과분리와 재검토

r6 후보 152개의 첫 수작업 분류는 유지 후보 76개·통합 검토 7개·정의 재구성 27개·
문맥/요구조건 이동 후보 19개·정의 보류 23개였다. **후속 원문·오류 주입 검증에서
이 분류 전체를 입증하지 못했다.** 76개를 검증된 속성 수로, 19개를 확정 삭제 목록으로
사용하지 않는다. 아래의 통합·이동·재구성도 제안이며 원문 관찰을 삭제하는 근거가 아니다.
한 공고에만 나온 후보 107개는 추가 확인 신호로 사용하며, 출현 빈도만으로 제외하지 않는다.

| 확인한 사례 | 문제 | 필요한 처리 |
|---|---|---|
| NIC 모델 081 / 150 | 같은 모델 속성이 장착 상태와 집계 설정 때문에 분리됨 | 속성과 대상 상태를 구별해 통합 검토 |
| NIC 포트 수 044 / 원문 표기 091 | 숫자와 `Dual Port` 표현 차이를 다른 속성으로 취급 | 원문 보존과 값 정규화를 분리; 미확정 관찰은 보류 |
| CPU 코어 수 003 / 원문 표기 149 | `16C` 해석 미완료를 새 속성으로 우회 | 원문 의미 확인 후 연결하거나 관찰 보류 |
| NIC 별도 공급 여부 147 | 082와 같은 인용이지만 082는 공급·장착 두 상태, 147은 공급 여부를 표현 | 같은 인용만으로 의미 중복을 단정하지 않고 상태/파생 플래그 정책 검토 |
| 중고·재생 부품 제안 금지 095 | 제안 금지 문장이 속성 이름에 들어감 | 제품 상태라는 성질·금지 연산자·적용 범위를 구별; 정보 자체의 제외는 확정하지 않음 |
| 서버 관리 기능 원문 116 | 프로토콜·KVM·모니터링·팬 제어를 하나의 속성으로 묶음 | 복합 조건과 기능 축을 재검토 |

배치용 통합 스크립트는 작성된 `measurement_basis` 문구·자료형·차원·집계·구성 상태의
일치로 그룹을 만든다. 이 문구를 일관되게 작성하고 의미를 검토하지 않으면 표현 차이가
새 ID가 된다. 반대로 복합 원문이 하나의 문구로 묶이면 서로 다른 기능도 한 속성에 남는다.
현재 코드의 signature 검사는 의미 통합의 충분조건이 아니다.

원문이 문자열이라는 이유로 숫자형 표준 속성의 문자열 버전을 만들지 않는다.
원문 값·인용은 관찰에 보존하고, 확인한 의미와 별도의 값 해석을 통해 표준 속성에
연결해야 한다. 이 분리는 후속 수정 기준이며 현재 초안에 구현·적용됐다는 뜻이 아니다.

이전 [후보별 1차 분류](../../.artifacts/procurement_specifications/server_dictionary_bootstrap_2026_10_20/granularity_audit/candidate_dispositions.csv)와
[분류 집계](../../.artifacts/procurement_specifications/server_dictionary_bootstrap_2026_10_20/granularity_audit/audit.json)는
수작업 제안 이력으로 남긴다. 현재 확인 범위와 정정 내용은
[원문·계약 재검증](verification/server_dictionary_bootstrap_2026_10_20.md#속성-단위-판단의-원문계약-재검증)을 따른다.
기존 원문·초안·승인 상태는 변경하지 않았다.

## 정의와 관찰의 구분

서로 다른 세 가지를 구별한다.

| 구분 | 예시 | 관리할 의미 |
|---|---|---|
| 구성요소 유형 | 시스템 메모리, 인버터 | 어떤 종류의 대상인가 |
| 속성 정의 | 기본 장착 메모리 용량, 인버터 정격출력 | 무엇을 측정·요구하는가 |
| 공고의 요구조건 | 8GB 이상, 3kW 이상 | 해당 공고에서 어느 대상에 어떤 조건을 요구하는가 |

속성 정의에는 ID·이름·정의·동의어·데이터 타입·기준 단위·적용 대상·집계 범위·
구성 상태·상태·버전을 관리한다. 타입과 단위만 같아도 의미가 다르면 분리한다.
기본/최대 지원 메모리, CPU 기본/부스트 클럭, 정확도/정밀도, SSD/HDD는 구분한다.

유형 사전의 메모리와 실제 공고의 ‘PC A에 장착할 메모리’는 다르다. 실제 대상은
문서별 ID와 소속 관계를 가진다. 요구값과 원문 근거는 요구조건에 두고 사전에 복사하지 않는다.

표현이 다른 동일 의미는 근거와 문맥을 확인해 동의어 후보로 제안한다.
매핑·신규 속성 제안·승인은 별도 단계이며 모델 판단만으로 사전을 자동 변경하지 않는다.
처리 순서는 [초기 사전 구축](dictionary_building_pipeline.md)을 따른다.
