# kordoc 고정 상태의 서버 규격서 선별 평가

이 기록의 본 평가는 **v1·v2의 당시 정책**에 대한 결과다. 이후 모델 구축 자료의 신뢰도를
우선하도록 기본 규칙을 v3·우선 확인만 선정으로 변경했다. 현재 정책과 별도의 학습용
검수 기준은 [선별 로직](document_identification.md)을 따른다. 아래 수치를 v3의 독립
평가 결과로 사용하지 않는다.

평가일은 **2026-10-20**이다. 파서는 **kordoc 4.22.15**, 옵션은 `ocr: false`, `images: false`로 고정했다. 파서 교체·대체 OCR·별도 파싱 엔진을 사용하지 않고 파일명·원천 참조 기반 선별의 적정성을 평가했다.

## 결론

**우선 확인 + 추가 확인**을 처리 대상으로 쓰는 정책이 우선 확인만 쓰는 정책보다 적절하다. 평가용 10개 공고에서 실제 서버·서버 용도의 워크스테이션 요구규격이 확인된 9개 공고 중 8개를 회수해 **공고 단위 회수율 88.9%**를 관측했다. GPU 카드만 증설하는 공고 1개는 실제 서버 납품 공고로 세지 않았다.

선정 파일 11개 중 10개에서 기술 규격을 확인해 **정밀도 90.9%**, 검토 가능한 실제 규격 문서 12개 중 10개를 찾아 **문서 단위 회수율 83.3%**였다. 공고 회수율은 모든 문서·조건을 회수했다는 뜻이 아니다.

평가용 미확인 파일 3개가 모두 미선정이어서 이들이 실제 규격을 포함하는 경우 전체 문서 회수율은 더 낮을 수 있다. 가능한 문서 회수율 범위는 **66.7~83.3%**다. 따라서 표본의 공고 회수 목표는 관측했지만 전체 문서 회수율 80%나 모집단 성능을 보장하지 않는다.

## 고정한 표본과 정책

- 원천 세부품명번호 4321150102가 있는 2026년 물품 공고의 최신 차수, 취소 제외·조회 시각 이하를 사용했다.
- 기존 개발 공고 20건과 추가 진단 2건, 총 22건을 제외했다.
- `server_selection_eval_2026_10_20_v1` seed와 공고번호·차수의 MD5 정렬 상위 20건을 고정했다.
- 앞 10건은 개발용, 뒤 10건은 평가용이다. 첨부가 없는 2건도 교체하지 않았다.
- 기본 선정 정책은 우선 확인 + 추가 확인이다. 우선 확인만 사용하는 좁은 정책은 비교 대상으로 별도 계산했다.
- 기본 v1을 먼저 동결했다. 개발 내용 검수 후 v2를 동결하고, 그 뒤 평가용 내용 검수를 진행했다.
- 평가용에서 발견한 오류를 보고 v2를 다시 수정하지 않았다. 다음 수정에 이 표본을 사용하면 새 평가 표본이 필요하다.

내용 검수는 assistant 단일 검수이며 전문가 이중 검수가 아니다. 규칙으로 생성한 후보 결과를 정답으로 사용하지 않고, kordoc의 반환 본문·표에서 실제 발주 기술 조건과 근거를 따로 기록했다. 원본 전체 시각 대조·authoritative Ontology 등록·운영 승인은 수행하지 않았다.

## 내용 판정 기준

실제 구매 대상의 성능·용량·치수·구성·명시 모델·기술 인터페이스·호환 조건이 있으면 규격 포함으로 검수했다. 숫자뿐 아니라 GPU 공식 지원과 Windows/Linux 호환성 같은 구체적인 정성 조건도 포함한다. 단순 품명·수량·예산·납기, 평가점수·참가자격·빈 서식·다른 문서를 보라는 참조만으로는 포함으로 세지 않았다.

공고·계약·평가 문서라는 이름만으로 내용 정답을 정하지 않았다. 규격 문서라도 텍스트가 없거나 요구 영역이 이미지로만 남았으면 미확인으로 기록했다. 실제 대상 품목이 서버인지도 내용 라벨과 별도로 검토했다.

## 다운로드와 파싱 비용

20개 공고의 첨부 68개를 모두 확보했다. 전체 전송량은 **11,969,860 bytes(약 11.42MiB)**로 파일당 5MiB·총 100MiB 예산 안이었다. 메타데이터 선별 자체는 네트워크·파싱·LLM을 호출하지 않는다. 검증에서만 선정·미선정 첨부를 함께 확보·파싱했다.

kordoc은 65개 파일에서 success, 3개에서 failure를 반환했다. failure는 PNG 2개의 MISSING_DEPENDENCY와 PDF 1개의 ENCRYPTED였다. success 중에도 빈 텍스트·규격 영역의 이미지 대체가 있어 내용 미확인은 총 6개였다. success를 규격 포함이나 검수 완료로 간주하지 않았다. 개발 표본 2개 공고는 첨부 메타데이터가 없어 별도 미확인이다.

## 개발 표본에서 수정한 공통 규칙

새 기본 버전은 **attachment_review_v2**다. 서버 코드별 예외나 단일 첨부 자동 승격을 추가하지 않았다. 개발 자료에서 실제 기술 규격을 확인한 아래 문서명을 추가 확인 역할로 더했다.

| 추가 문구 | 개발 원문에서 확인한 내용 |
|---|---|
| 규격비교조사표 | 기입된 요구 사양과 제조사별 충족 여부 |
| 산출내역서 | 실제 구매 서버 구성과 랙 치수 |
| 용도설명서 | 도입 예정 장비의 CPU·GPU 등 구성 |
| 인프라구성도 | TO-BE 서버·장비 연결, API·DICOM·PoE 등 기술 구성 |

| 개발용 10건·36개 첨부 | v1 | v2 |
|---|---:|---:|
| 검수된 선정 파일 정밀도 | 83.3% (5/6) | 90.0% (9/10) |
| 검수 가능한 규격 문서 회수율 | 50.0% (5/10) | 90.0% (9/10) |
| 선정 파일 수 | 8 | 12 |
| 내용 미확인 | 선정 2·미선정 1 | 선정 2·미선정 1 |

이 개선치는 개발 자료의 결과다. 평가 표본에는 추가한 네 역할의 새 일치가 없어 v1과 v2의 평가 수치는 동일했다. 별도 표본에서도 같은 폭으로 개선됐다고 주장하지 않는다.

## 평가용 10건·32개 첨부 결과

| 지표 | 우선 확인만 | 우선 + 추가 확인(기본) |
|---|---:|---:|
| 실제 서버 공고 회수 | 7/9 (77.8%) | 8/9 (88.9%) |
| 선정 파일 정밀도 | 8/8 (100.0%) | 10/11 (90.9%) |
| 확인 가능한 규격 문서 회수 | 8/12 (66.7%) | 10/12 (83.3%) |
| 선정 파일 수 | 8 | 11 |
| 선정 파일 bytes | 660,268 | 1,154,742 |
| 전체 파일 bytes | 4,951,141 | 4,951,141 |

같은 선별을 운영에 적용한다고 가정하면 기본 정책은 전체 대비 파일 수 **65.6%**, byte **76.7%**를 줄일 수 있는 선정량이었다. 이번 검증은 전체 첨부를 실제로 내려받았으므로 검증 중 이미 그 비용을 절감했다는 뜻은 아니다. 파서 CPU 시간 절감률도 측정하지 않았다.

공고 회수율은 알려진 실제 서버 규격이 있는 공고를 기준으로 계산했다. 일부 미선정 첨부가 미확인이어도, 이미 서버 규격이 확인됐고 선정 집합에 가능한 회수 문서가 전혀 없으면 확정 누락으로 센다. 반대로 미확인 선정 문서가 있으면 회수 성공이나 확정 누락으로 단정하지 않는다. 완전 검수된 공고만 골라 누락 공고를 숨기지 않았다.

표본 8/9의 Wilson 95% 구간은 **56.5~98.0%**다. 표본이 작고 단일 검수이므로 모집단에서 최소 80%를 보장하는 통계적 근거는 아니다.

## 다음 개선의 기준

현재 정책은 서버 공고의 1차 선별에 사용할 근거를 얻었으며 우선 확인만으로 범위를 줄이면 이번 표본에서 공고 회수율이 80% 아래로 내려간다. 다만 운영 승인이나 모든 물품의 품질 검증이 완료된 것은 아니다.

평가기준서·일반 구매목록·사양 이미지에 대한 누락과 제출용 제안요청서 오선정을 다음 개발 사례로 축적한다. 평가 파일명을 보고 즉시 특례를 넣어 같은 표본으로 재합격시키지 않는다. v3를 만들면 이번 평가 표본은 개발 자료로 전환하고 새 평가 표본을 고정한다. kordoc 고정 원칙과 미확인 분리는 유지한다.

## 실행 검증

Pipeline 테스트 **189 passed, 16 skipped**, 기존 Prefect Mermaid 관련 경고 1개.
선정 정책·미확인 범위·누락 공고 집계·버전 재현을 테스트했다. 이 테스트 수는 문서
품질 정답의 전문가 승인이나 모집단 성능 검증을 뜻하지 않는다.

## v3 정밀도 우선 정책의 사후 점검

v3는 참조 문구만으로 우선 확인에 승격하지 않고, 기본 선정도 우선 확인으로 한정한다.
v1·v2 결과·라벨은 변경하지 않고 같은 자료로 사후 점검했다. 평가 자료의 후보 8개 중
8개에서 규격을 확인했고 오선정 0개, 서버 공고 회수 7/9, 확인된 문서 회수 8/12였다.
개발 자료에서는 후보 6개 중 4개가 규격 포함, 2개가 미확인이었다. 새 독립 검증이나
학습용 검수 승인이 완료된 것은 아니다. 후보를 그대로 학습 양성으로 사용하지 않는다.

사후 점검 산출물은 같은 실험 루트의 `v3_precision_policy_retrospective.json`이다.
이전 `results.json`·`errors.json`은 당시 정책의 결과로 유지한다.
