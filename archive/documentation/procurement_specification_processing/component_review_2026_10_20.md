## 결론

기존 다품목 결과를 그대로 정확하다고 볼 수는 없었다. 원문 대조에서
**레일 키트 누락 2건, 납품·확장 범위 혼합 1건, 구성요소 세분화 보완 1건**을
발견해 새 실행 결과로 수정했다. 구조가 다른 PDF·DOCX 2건도 추가 분석했다.

수정 후 3개 문서의 인용·참조·입력 이력 검사와 CLI 실행이 통과했고,
선정한 의미 수용 조건 17개를 Codex가 원문과 대조해 확인했다.
이는 **Codex의 원문 기반 자기검토**다. 독립적인 정답 라벨 평가나 모든 물품의
정확도 검증은 아니며 Precision·Recall을 산정하지 않았다.

내장 포트·슬롯 등의 원문은 소유 구성요소 구간에 보존할 수 있고, 소프트웨어는
설치 환경 단위로 묶을 수 있다. 원자 요구조건·개별 소프트웨어 버전의 완전 추출은

## 추가 문서에서 확인한 사항

PDF 표본은 CPU·메모리·서로 다른 SSD 2종·GPU·관리 소프트웨어 라이선스·CPU 캐리어·
전원 연결 케이블·NIC의 9개 후보로 분석했다. 병합된 ‘디스크’ 아래 두 행을 별도
대상으로 유지했다. ‘보조장치’는 문서 그룹으로 남기고 그 아래 소프트웨어·캐리어·
케이블·NIC를 구분했다. 보증 서비스 행은 부품으로 만들지 않았다.

DOCX 표본은 현재 GPU 구성과 향후 확장 지원을 같은 셀에서도 별개 역할로 보존했다.
배관·피팅·펌프·라디에이터는 냉각 시스템의 하위 구성으로 연결했다. 데이터 통신과
관리 통신은 역할별로 구분했다. 기타 요구사항에 있는 케이블·냉각수·전원 부자재·
매뉴얼도 확인했다. ‘수냉 블록 또는 동등 방식’을 특정 블록의 무조건 납품으로
확정하지 않았고, Ubuntu·Rocky Linux도 두 OS 모두 필수로 만들지 않았다.

## 검증기가 잡지 못하는 오류도 시험

정상 원문 인용을 유지한 채 의도적으로 잘못된 제안을 넣었다.

| 음성 대조 | 구조 검사 결과 | 확인한 한계 |
|---|---|---|
| CPU 후보의 이름·유형을 GPU로 변경 | `passed`, 검토 대기 | 인용 존재가 의미적 동일성을 증명하지 않음 |
| CPU 후보 이름을 근거 없는 장치명으로 변경 | `passed`, 검토 대기 | 자유로운 의미 후보명은 코드가 원문 의미와 자동 대조하지 않음 |
| 서버 레일 키트를 다시 제거 | `passed`, 검토 대기 | 참조 무결성 검사가 구성요소의 완전성을 보장하지 않음 |

따라서 이 모듈의 `passed`를 의미 검수 통과나 승인 라벨로 사용해서는 안 된다.
이 계약 경계를 회귀 테스트에 추가했다. 자동으로 승인 상태를 바꾸거나, 특정
품목의 단어 목록을 넣어 의미 검증이 해결된 것처럼 처리하지 않았다.
