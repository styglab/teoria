# 데이터 확대 전 자동 처리·의미 평가 검증

## 결정

서버 문서를 곧바로 100건으로 늘리지 않는다. 소수 문서에서 자동 추출·규격 귀속·
고정 사전 매핑과 의미 평가를 확인한 뒤 Harness2 개발 평가를 연결하고 확대한다.
목표 분할은 구축 80건·개발 검증 20건·별도 최종 검증 20건이다.
최종 검증을 반복 개선용으로 사용하지 않는다.

## 이번 변경

- `semantic_evaluation run`: 실제 Codex 호출로 추출·연결 후 고정 사전 재사용을 제안한다.
  재사용, 신규 의미, 적용 대상 누락, 원문 모호성, 속성 사전 제외를 구분한다.
  미해결 대상을 가진 속성의 재사용과 종류·차원·적용 대상 위반을 거부한다.
- `semantic_evaluation score`: 별도 원문 기반 기대 사례와 금지 매핑을 평가한다.
  같은 예측 하나로 기대 관찰 두 개를 충족시키지 않는다. 추론 경로에 정답을 주지 않는다.
- `prepare --chunk-chars`: 원문 줄과 노드 ID를 보존하는 구간별 추출 옵션을 추가했다.
  앞 구간의 엔티티를 재사용하고 구간별 ID와 인용을 검증한다. 구간 간 동일성·논리는
  검토 이슈로 남긴다. 긴 단일 줄은 자르지 않으므로 엄격한 토큰 상한은 아니다.
- 실패 시 단계·시간·오류를 저장한다. 원문이나 사전을 변경하거나 수작업 예측으로
  실패를 대체하지 않는다. Harness2 기존 코드와 corpus는 보존했다.

## 실제 실행과 한계

입력은 기존 서버 구축 문서 `server_07` 한 건이며 개발용이다. 과거에 읽은 문서이므로
새 검증셋이나 독립 정답 평가로 취급하지 않는다. 사전은 서버 r2 초안을 고정했다.
예상 의미 사례 7개를 예측 전에 별도 파일과 해시로 고정했다. 현재 Codex가 작성한
silver 사례이며 사람 검수 정답이 아니다.

| 실행 | 실제 결과 |
|---|---|
| 간단한 JSON 추론 호출 | 약 6초에 완료 |
| 문서 전체 추출, 90초 제한 | 시간 초과 |
| 문서 전체 추출, 180초 제한 | 약 180초 후 시간 초과 |
| 배열 전송 형식 축약 실험, 120초 제한 | 시간 초과; 활성 코드에서 제거 |
| 350자 기준 구간별 추출, 호출당 90초 제한 | 4개 구간 중 첫 구간 검증 통과, 다음 구간에서 시간 초과 |

따라서 실제 문서의 자동 추출 → 연결 → 매핑을 끝까지 완료했다고 표시하지 않는다.
실제 문서 의미 채점도 아직 실행하지 못했다. 구간 옵션이 구현·단위 검증됐다는 사실과
전체 문서 실행 성공은 구분한다. 시간 초과의 세부 원인이 출력량·추론 지연 중 무엇인지는
추가 계측이 필요하며 확정하지 않는다.

실행 자료는 `.artifacts/procurement_specifications/semantic_readiness_2026_10_21/`에 있다.
`automatic_r1/failure.json`, `automatic_compact_r1/failure.json`,
`automatic_windows_r1/failure.json`에 실제 실패가 남아 있다. `batch_windows/inference/`에는
첫 구간의 원래 응답·수정 응답과 Codex 호출 receipt가 있다. `references.json`과
`references_freeze.json`은 별도 기대 사례다. 운영 사전 변경·승인·게시는 없다.

## 코드 검증과 다음 확인 조건

전체 Pipeline 테스트는 **204 passed, 19 skipped**다. 기존 Prefect 경고 1개가 있다.
관련 검사는 적용 대상 누락 분리, 미해결 대상·CUDA/CPU 코어 오병합 거절,
누락·대상 오귀속·장착/지원·총합/개별 혼동 검출, 일대일 기대 관찰 대응,
구간 간 근거 혼용 거절, 원문 보존, 실행 순서와 실패 기록을 포함한다.
단위 테스트는 실제 모델의 의미 정확도나 처리 속도를 보장하지 않는다.

100건 확대와 Harness2 Semantic IR 개선 실행은 아직 진행하지 않았다.
다음 확인 대상은 구간별 추론 지연·출력량 계측과 작은 구간의 자동 완료다.
이를 완료한 뒤 연결·매핑 및 고정 사례 채점을 실행하고, 개발 문서에서 Harness2
기준선·후보를 비교한다. 현재 기존 Harness2의 수치 QA task를 새 의미 평가에 연결했다고
기록하지 않는다. 이후 전체 기대 관찰과 검수 정답을 갖춰 누락률까지 측정해야 한다.

## 후속 진단과 중단

200자 구간에서는 실제 응답을 받았으나 `dimension`에 영문 코드 대신 한글 설명이
들어가 검증에 실패했다. 단위별 차원 계약과 관찰 ID를 포함하는 오류 메시지를 추가했다.
이전 구간 수정으로 다음 구간 입력이 달라질 때 캐시가 불일치를 거절한 사례도 확인해
입력과 수정 피드백별 캐시 경로를 분리했다. 이 보완의 전체 실제 문서 성공은 미확인이다.

사용자가 30분 이상의 소요 시간을 지적해 마지막 실행을 중단했다. 최종 시도는 6개 구간
중 첫 구간까지만 완료했으며 문서 완료·매핑·의미 채점 결과는 없다. 경과 시간은 여러
실험·코드 수정·테스트·재시도를 포함하며 문서 한 건의 정상 처리 시간으로 해석하지 않는다.
`automatic_contract_v1/interrupted.json`에 중단을 기록했다. 추가 추론 재시도는 하지 않았다.
