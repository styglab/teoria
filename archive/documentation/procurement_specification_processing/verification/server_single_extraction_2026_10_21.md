# 서버 한 건 최소 추출과 원문 대조

이전 전체 배치의 반복 디버깅을 중단하고 **파싱된 문서 한 건 → 추출 JSON 하나 → 원문
대조**만 실행했다. 사전 매핑·차원 코드·구간 분할·자동 수정 호출·Harness2를 붙이지 않았다.

## 실제 결과

입력은 `server_07`, 공고 `R26BK01779237`의 서버컴퓨터 규격서다. 이전부터 읽은 개발
문서이며 신규 검증셋은 아니다. 저장된 native JSON에서 노드 ID를 유지한 줄 ID를 만들고
모든 비어 있지 않은 원문 줄을 제공했다. 파서나 OCR을 다시 실행하지 않았다.

실제 `CodexRunner` 호출 **1회, 52.802초**에 JSON을 받았다. 대상 8개, 관계 7개,
규격·조건 29개를 추출했다. 원문 명칭·값의 부분문자열 존재, 근거 줄 ID, 대상 ID의
유일성, 규격·관계의 대상 참조 검사를 통과했다. 반환된 JSON을 사람이 작성한 결과로
대체하거나 자동 재호출하지 않았다.

| 대상 | 추출 예 |
|---|---|
| 서버컴퓨터 | Dell PowerEdge R770, 1개, NO OS, 납품·검수 기한 |
| CPU | Intel Xeon 6 6517P, 16C, 190W, 3.2GHz, 2EA |
| Memory | 256GB |
| SSD | 960GB, SATA, 2EA |
| NIC | Broadcom 57414, 2Port, 25GbE, SFP28, OCP 3.0, 2EA |
| HBA | Agnostic, 2Port, 32GB, PCIe, 2EA |
| Power Supply | 110W, 2EA |
| ProSupport | 4-시간 방문 서비스, 포함, 36 개월 |

서버에서 여섯 하드웨어 대상으로 향하는 관계는 규격 관계로 표현했다. ProSupport는
서버를 서비스 대상으로 연결했다. 근거 없는 물리적 포함 관계는 확정하지 않았다.
A/B 반복 사양은 같은 관찰로 묶어 양쪽 원문 줄을 연결하고 수량을 합산하지 않았다.

## 원문 대조

현재 Codex가 원문과 반환 JSON을 대조한 뒤 대상 귀속·값 보존·반복 수량·모호성 등
선택 검사 10개를 실행했다. 모두 통과했고, 주요 규격·조건 구절 11개 모두 추출 규격의
근거로 연결됐다. 이 수치는 사후 자기검토이며 독립 정답의 정확도·재현율이 아니다.

CPU 클럭의 기본/최대 구분, 메모리의 총량/모듈당 구분, CPU 전력 측정 기준,
HBA `32GB`의 의미, 서비스 `4-시간`의 기준은 불명확한 상태로 남겼다. `32GB`를
`32Gbps`로, 전원 `110W`를 다른 수치로 바꾸지 않았다.

## 산출물과 판단

경로는 `.artifacts/procurement_specifications/server_single_extraction_2026_10_21/`다.

- `source.json`, `instruction.txt`, `input_receipt.json`: 실제 입력·지시와 해시
- `run.py`: 한 번 호출하고 원문 존재·참조를 확인하는 실험 스크립트
- `extraction.json`, `extraction.receipt.json`: 실제 모델 응답과 실행 receipt
- `review.json`, `summary.json`: 원문 대조와 시간·관찰 수
- `report.html`: 대상별 규격·관계와 원문 근거를 볼 수 있는 결과

이 문서 한 건에서는 최소 추출 흐름이 완료됐다. 앞선 30분 이상의 디버깅을 정상적인
문서 처리 시간으로 해석하지 않는다. 고정된 작은 출력 계약으로 먼저 결과를 확인하는
순서를 유지한다. 다른 문서·긴 표의 일반화, 표준 개념 매핑, 전체 배치의 처리 속도와
정확성, 100건 확대 및 Harness2 고도화는 아직 검증하지 않았다. 기존 Harness2는 보존했다.
