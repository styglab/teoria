# FormatID 결과 탐색 화면 배포 — 2026-10-31

## 변경과 배포 범위

FormatID를 규격서별 실행 결과를 읽는 앱으로 정리했다. 프로파일 후보 비교·Draft 생성·검토·승인
탭과 사용하지 않는 전용 프런트엔드 코드를 제거했다. 기존 의미 관리 API와 승인 이력은 유지한다.

규격서 선택과 문서별 결과 행은 `document` URL 값으로 연결한다. 엔티티 목록·구성/포장 계층,
속성·관계·원문 근거를 표시하고, 관계는 출발·도착 대상과 방향을 보존한다.
보류 관계·귀속/근거 누락 속성·추출 범위 미해결 기록은 읽기 화면에 모은다.
실패·제외 문서는 빈 성공 결과로 바꾸지 않는다. 이전 `tab=review` 링크는 결과 화면으로 연결하고
`review_revision`을 제거하며 승인 동작을 실행하지 않는다.

기존 Compose 프로젝트 `teoria`와 세 모듈 구성을 유지하고 `nginx`만 빌드·교체했다.
Admin API·Worker·DB migration·게시 artifact는 이번 변경으로 교체하거나 적용하지 않았다.

## 검증

- 프런트엔드 21개 테스트 파일·84개 항목 통과. 다중 문서 선택, 이전 URL 호환,
  관계 방향·대상 이동, 보류 관계·미지정 속성의 근거, 실패 문서 구분을 포함한다.
- TypeScript·Vite 프로덕션 빌드와 문서 검사 9개 항목 통과.
- 실제 Admin API를 사용하는 개발 미리보기와 배포된 게이트웨이에서 Chromium으로 확인했다.
  저장된 규격서 1개에서 문서 선택 URL의 새로고침 복원, 관계 4개의 방향,
  원문 패널과 미해결 항목을 탐색했다. 다중 문서 전환은 컴포넌트 테스트에서 확인했다.
- 데스크톱에서 엔티티·상세·근거 3열을 확인했다. 모바일 390px에서 페이지 가로 넘침은 없었다.
- FormatID 승인 컨트롤 0개, 브라우저 검증 중 쓰기 API 호출 0건,
  브라우저 예외·서버 5xx 응답 0건이었다.
- 게이트웨이 정적 JS/CSS가 검증한 `frontend/dist`와 같은 checksum임을 확인했다.
  기존 자산 조회·인증·규격서 이력 조회도 정상 응답했다.

## 정리와 한계

교체 전 Web 컨테이너가 제거됐음을 확인했다. 모든 실행·중지 컨테이너와 다른 프로젝트의
배포 상태가 참조하지 않는 이전 Web 이미지 1개만 강제 옵션 없이 삭제했다.
현재 이미지 참조는 `deploy/compose/.state/teoria/deployment.json`에 반영했다.
상세 전후 상태는 같은 디렉터리의 `formatid_results_before.json`,
`formatid_results_after.json`, `formatid_results_verification.json`에 보관한다.

새 문서 처리나 업무 의미의 승인·게시는 실행하지 않았다. 이 검증은 결과 화면과 배포 확인이며
추출 의미의 정확도나 모든 문서의 품질을 보장하는 평가가 아니다.
이전 Web 이미지는 로컬 rollback 대상으로 남아 있지 않다.
