# Python 구현과 kordoc 4.22.15 비교

검증일: 2026-10-20. Python 패키지: `kory-parser` 0.1.0.
원본과 동일한 파일 hash를 확인하고 실제로 두 엔진을 실행했다. 설치 방법과 기능별
구현/미이식 범위는 [사용 안내](usage.md)에 있다.

**패키지 작성·빌드·원본 비교는 완료했지만, 원본 kordoc의 전체 기능 이식이나
동등 품질 검증이 완료된 상태는 아니다.** 특히 PDF 파서는 다른 Python 엔진을
사용한 재구현이며, 원본의 표·레이아웃 알고리즘 전체를 포팅하지 않았다.

## 비교 범위와 해석

- 기존 첨부 corpus **68개**: HWP 21, HWPX 10, PDF 32, DOCX 1, XLSX 2, PNG 2.
- 이전 파서 비교의 주요 표본 **10개**도 별도로 재실행했다. 이 10개는 위 68개에
  포함되므로 **78개 독립 표본으로 합산하지 않는다**.
- 실제 문서 비교에서는 양쪽 모두 OCR·수식 OCR·이미지 바이트 추출을 껐다.
- 원본 HWP/HWPX에는 `layoutTables="keep"`, `keepTrailingEmptyCols=true`,
  `keepEmptyParagraphs=true`를 적용했다. 공통으로 머리말/꼬리말 제거와 반복 제거를 껐다.
- Python은 자체 보존 계약을 사용했다. HWP/HWPX의 페이지는 section 근사이며,
  XLSX 빈 행·열을 보존하는 등 설정/계약 자체에 차이가 있다.
- 아래의 "본문 일치"는 공백·줄바꿈과 일부 Markdown 표시를 정규화한 결과다.
- "격자 일치"는 표 순번별 행·열·anchor 주소·row/col span이 같은 경우다.
  "셀까지 일치"는 같은 격자의 셀 텍스트까지 같은 경우다.
- "본문+셀 일치"는 양쪽 실행이 성공하고 정규화한 전체 본문과 모든 표·셀 내용이
  같은 경우다. 글꼴·스타일·metadata·이미지·물리 위치·의미 정확도의 전체 일치는 아니다.
- 원본 출력과의 일치율은 원문 대비 정확도가 아니다. 원본의 누락을 정답으로
  취급하지 않으며 전체 문서 시각 검수나 업무 의미 검수는 수행하지 않았다.

## 68개 실제 문서 결과

| 형식 | 표본 | Python 실행 성공 | 본문 일치 | 격자 일치 | 셀까지 일치 | 본문+셀 일치 |
|---|---:|---:|---:|---:|---:|---:|
| HWP | 21 | 21 | 13 | 21 | 18 | 12 |
| HWPX | 10 | 10 | 10 | 10 | 10 | 10 |
| PDF | 32 | 29 | 12 | 7 | 7 | 5 |
| DOCX | 1 | 1 | 1 | 1 | 1 | 1 |
| XLSX | 2 | 2 | 2 | 0 | 0 | 0 |
| PNG | 2 | 0 | 0 | 0 | 0 | 0 |
| **합계** | **68** | **63** | **38** | **39** | **36** | **28** |

본문·격자·셀 열은 양쪽 실행 성공을 조건으로 집계했다. 표가 없는 문서는 양쪽
모두 표가 없으면 격자 일치에 포함된다. 따라서 39는 **표 39개를 검증했다는 뜻이 아니다**.

원본은 65개 success와 3개 failure를 반환했다. Python은 PDF 암호화 1개,
native text가 없는 PDF 2개, OCR을 끈 PNG 2개를 실패로 반환했다.
원본은 텍스트가 없는 PDF 2개에서도 success를 반환하므로 실행 성공 건수를
품질 우열로 해석하지 않는다. Python 성공 63개 중에도 규격 영역이 이미지로 남는
문서가 있다. `UNEXTRACTED_IMAGE_TEXT` 등 진단을 별도로 확인해야 한다.

문서별 상세 수치와 입출력 hash는
[`verification/results/corpus_68.json`](../verification/results/corpus_68.json)에 있다.
본문 없는 경우의 문자 F1=1 같은 수치만 성공으로 집계하지 않았다.

## 확인한 개선과 남은 차이

첫 실행에서 드러난 HWPX 삭제 marker의 tail text 노출, 중첩 표 내부의 `cellSpan`을
바깥 셀 span으로 읽던 오류, PDF 암호화 예외 분류, OCR 좌표의 NumPy float JSON
직렬화 문제를 수정했다. 직접 만든 회귀 표본으로 변경 추적·중첩·실패 분류를 확인했다.
HWP/HWPX 자동 번호·글머리표도 추가 이식했다.

남은 차이는 아래와 같다.

1. **PDF**: 페이지를 넘는 표 연결, 표 안 표의 세부 행, 틀 표/실제 데이터 표 구분,
   클리핑·무괘선 기반 탐지, 한국어 줄 이음과 복잡한 읽기 순서가 원본과 다르다.
   현재 가장 큰 차이이며 이 결과로 Python 엔진을 운영 기본 파서로 교체하지 않는다.
2. **HWP**: 표 격자는 21개 문서 모두 일치했지만, 일부 자동 기호·주석/입력 안내문·
   머리말/꼬리말의 위치와 셀 문구에 차이가 있다. 선택적으로 사라진 기호나 표 밖으로
   이동한 문구를 문자 F1만으로 통과시키지 않는다. PUA를 표시 문자로 바꾼 차이도 있다.
3. **XLSX**: 본문 문자는 두 문서 모두 일치했지만 Python이 빈 행·열과 원본 셀 좌표를
   유지해 원본의 압축된 표 격자와 다르다. Excel 표시 형식(날짜·수치 등)도 완전 이식하지 않았다.
4. **HWP3/HWPML/XLS/PPTX**: 구현과 소형 합성 단위 검증은 있으나 이번 실제 문서
   corpus에 없으므로 원본과의 실제 문서 동등성을 주장하지 않는다.
5. **수식·서식·조판·암호/손상 복구**: 원본의 모든 경로와 옵션을 옮기지 않았다.
   전체 API 호환 버전으로 취급하지 않는다. 세부 목록은 사용 안내에 있다.

## 테스트·OCR·배포 검증

- 독립 패키지 테스트 **34개 통과**. 테스트에는 HWP5 OLE/record·병합,
  HWP3 stream/조합형, HWPX 변경 추적/중첩/자동 번호, HWPML, DOCX 수직 병합,
  XLSX, BIFF XLS, PPTX, PDF 위치·표, 이미지 실패, 입력 한도, 비교 지표 오해 방지가 포함된다.
- `ruff check`와 형식 검사 통과.
- wheel과 sdist를 빌드하고 소스 디렉터리와 다른 격리 환경에 wheel을 설치해
  HWPX 파싱을 실행했다. subprocess 호출을 막은 상태에서도 파싱이 성공했다.
- wheel/sdist의 문자 mapping과 원저작권 고지·rhwp MIT license 포함을 확인했다.
- 선택 OCR을 설치해 직접 만든 한국어 이미지 1줄
  `서버 CPU 32 메모리 64GB`를 실제 인식하고 JSON 직렬화까지 확인했다.
  이것은 동작 smoke test이며 OCR 정확도 benchmark나 원본 OCR 비교가 아니다.
- 실제 문서 원문과 native JSON은 `.artifacts/` 안에만 보존했다. 배포 패키지에는 넣지 않는다.
- 실제 Prefect Job·운영 API·배포 검증은 하지 않았다. 이 문서는 운영 배포 성공 기록이 아니다.

Python 소스 hash, 원본 npm integrity/bundle hash, 의존성 버전은
[`verification/provenance.json`](../verification/provenance.json)에 있다.
최종 비교 두 세트는 같은 Python 소스 hash를 사용했다. 실행 시간은 문서당 1회
측정이며 초기화/캐시 조건이 달라 속도 순위로 사용하지 않는다.
