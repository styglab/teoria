# 납품 품목 중심 파이프라인 v2 교체 검증

2026-10-22 사용자 요청으로 기존 의미 분석 경로를 교체했다.
현재 계약과 실행 명령은 [납품 품목 중심 분석 배치](retired_semantic_batch.md)를 따른다.

## 변경 범위

- 기존 일괄 `extract` → `link` 흐름과 문자 수 기반 구간 분할을 제거했다.
- `identify` → 품목별·공통 `extract` → `resolve` → `validate` → `integrate`로 재작성했다.
- 품목 소속과 직접 규격 대상, 공통·품목 간·미귀속 범위를 구분한다.
- 동일 대상은 별칭 연결로 표현하며 원래 관찰과 원문 근거를 보존한다.
- 품목 간 조건 논리는 원문 근거를 가진 추가 그룹으로 연결하고 기존 조건은 보존한다.
- 검토 오류는 의미 통합과 고정 사전 재사용을 차단한다.
- 기존 원본·파싱 입력, 근거 표현·모델 호출 기반 코드, Harness2·검색 평가 경로는 보존했다.
- 다운로드·파서·DB·Prefect·Runtime·Registry·Ontology 게시는 연결하지 않았다.

## 실제 서버 문서 실행

입력은 기존 개발 문서 `server_07`, 공고 `R26BK01779237`의 저장된 원본·native JSON·
파서 실행 기록이다. 신규 독립 검증셋이 아니다. 기존 응답이나 수작업 예측으로 대체하지
않고 실제 Codex 호출을 사용한다.

첫 revision은 품목 식별이 **28.278초**에 완료됐다. 서버컴퓨터 1개와 모델명을 같은
품목으로 식별하고 CPU·메모리·서비스를 별도 납품 품목으로 생성하지 않았다.
상세 추출은 **120.146초**에 시간 초과됐으며 후속 단계는 실행하지 않았다.

두 번째 revision은 인용을 짧게 하고 반복 규격은 관찰 하나와 복수 근거로 표현하도록
지시했다. 호출 제한은 240초다. 첫 revision의 실패 기록은 보존한다.

두 번째 revision의 원시 응답은 내부 대상 7개·조건 29개·관계 7개였지만,
차원에 한국어 의미명과 `quantity`·`capacity` 등의 미지원 코드를 사용했다.
수정 호출도 차원 계약을 통과하지 못해 extract 단계가 **362.697초**에 실패했다.
공통 구간·resolve·validate·integrate는 실행하지 않았다. 원시 JSON 생성을 계약 검사
완료로 보고하지 않는다.

세 번째 revision은 차원을 스키마의 선택값으로 제한하고 단위별 차원표를 입력에
제공한다. 기본 호출 제한도 240초로 맞췄다. 이전 실패 응답을 수작업으로 고쳐
승인된 예측으로 사용하지 않는다.

세 번째 revision은 차원 계약을 통과했지만 원문에 없는 속성명 3개를 `property_raw`에
기록했다. 수정 호출 뒤에는 포함 서비스를 `delivery_member_of`로 연결한 관계 오류가
검출되어 extract 단계가 실패했다. 의미가 다른 관계를 허용하도록 검사를 완화하지 않았다.

네 번째 revision은 원문 속성명이 없을 때 null을 사용하는 예시와 관계별 방향·허용 대상을
명시했다. 수정 가능한 원문 필드·차원·연산자·관계 오류를 함께 전달하도록 검사도 보완했다.
동일 입력·동일 schema·동일 identify 프롬프트의 추론 캐시만 해시 검사 후 재사용한다.
추출과 후속 단계는 새 프롬프트로 실행한다.

네 번째 revision은 추출 계약을 통과했다. 품목별·공통 2회 호출에 **204.055초**로
서버 1품목·내부 규격/서비스 대상 7개·요구조건 28개·관계 7개·논리 그룹 1개를 저장했다.
문서 전체 정리는 **81.591초**, 모델 원문 검토는 **55.517초**였다.
검토는 메모리 총량·HBA 32GB·방문 서비스 시간의 모호성 3건을 남겼다.
품목 누락·과분리·다른 품목으로의 귀속·추가 조건 누락은 이 모델 검토에서 지적되지 않았다.
이는 독립 정답의 정확도 측정이 아니다.

이 검토는 이전 단계의 `validation_error`·`source_node_ids`에 대한 처리 메모를 현재 입력에
없는 원문 사실로 오인한 source_error 1건도 기록했다. 게이트가 사전 통합을 차단했다.
실제 식별 단계에는 수정 호출이 있었고 추출 단계에는 source_node_ids가 제공되어 있었다.
원문 조건 오류와 처리 이력에 대한 서술을 구분하는 입력이 부족했다.

다섯 번째 revision은 검토 입력에 실제 이전 단계의 응답·수정 응답·원문 구간 정보를
제공하고 처리 메모가 원문 사실이나 승인 기록이 아님을 명시한다. 식별·추출·정리는

이전 검토는 재사용하지 않고 검토부터 다시 실행한다. source_error를 수작업으로
삭제하거나 검사 조건을 완화하지 않았다.
