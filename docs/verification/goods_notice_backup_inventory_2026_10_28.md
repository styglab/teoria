## 복원 설계에 반영할 사항

1. 공고번호·차수와 원문 해시를 보존하고, 첨부는 공고·슬롯·원본 URL을 연결하는 목록으로
   구성한다. 같은 파일명만으로 병합하지 않는다. 원문 파일명과 URL을 함께 보존한다.
2. 이 백업의 공고 테이블은 각 공고번호·차수의 저장 당시 상태다. 같은 차수에서 발생한
   과거 수정 전체가 보존됐다고 간주하지 않는다. 신규 관측 시각과 해시별 변경 이력을
   별도로 설계하고 복원 기준 시각을 기록한다.
3. `chgDt`가 있는 행은 15,932건이다. 변경 시각이 항상 존재한다고 가정한 checkpoint를
   만들지 않는다. 증분·과거 수집의 범위와 실제 Provider 계약을 확인한 뒤 재수집 정책을 정한다.
4. 예전 다운로드·저장 상태나 enrichment claim을 실행 가능한 상태로 복원하지 않는다.
   추출 COPY는 보존·staging 입력이며 운영 DB에 직접 적용할 복원 SQL이 아니다.
5. 첨부 목록 저장과 명시 선택 문서의 규격서 처리를 구분한다. 구형 첨부 자동 파싱·참가자격
   판단 Flow를 연결하지 않는다. URL 유효성 확인은 다음 단계에서 별도 실행 기록으로 남긴다.
